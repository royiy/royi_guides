## מה זו כתובת IP?

כתובת IP (Internet Protocol Address) היא מזהה ייחודי (לוגי) של מכשיר ברשת, המאפשר לו לתקשר עם מכשירים אחרים באמצעות פרוטוקול IP (שכבה 3 במודל OSI). קיימות שתי גרסאות עיקריות בשימוש: **IPv4** (הנפוצה עדיין ברוב הרשתות) ו-**IPv6** (הדור הבא, שנועד לפתור את מחסור הכתובות ב-IPv4).

כתובת IPv4 מורכבת מ-32 סיביות (Bits), המחולקות ל-4 קבוצות (Octets) של 8 סיביות כל אחת, ומוצגות בייצוג עשרוני מופרד בנקודות (Dotted Decimal), למשל `192.168.1.10`. כל כתובת IP מורכבת משני חלקים לוגיים: **חלק הרשת (Network ID)** וחלק המארח (**Host ID**) - היחס ביניהם נקבע על ידי **מסכת הרשת (Subnet Mask)**.

### עקרונות מפתח

- **Subnet Mask** — מגדירה אילו סיביות בכתובת שייכות לחלק הרשת ואילו לחלק המארח. לדוגמה `255.255.255.0` = 24 סיביות רשת ו-8 סיביות מארח.
- **CIDR Notation (Classless Inter-Domain Routing)** — סימון מקוצר של המסכה, לדוגמה `192.168.1.0/24` במקום לכתוב `255.255.255.0` בנפרד.
- **Private vs Public IP** — טווחי IP פרטיים (RFC 1918) שאינם ניתובים באינטרנט הציבורי, לעומת כתובות ציבוריות המזוהות ברשת העולמית.

## טווחי IP פרטיים (RFC 1918)

| טווח | Subnet Mask | מספר כתובות | שימוש טיפוסי |
|---|---|---|---|
| `10.0.0.0 – 10.255.255.255` | `/8` | ~16.7 מיליון | רשתות ארגוניות גדולות, Cloud (VPC) |
| `172.16.0.0 – 172.31.255.255` | `/12` | ~1 מיליון | רשתות ארגוניות בינוניות |
| `192.168.0.0 – 192.168.255.255` | `/16` | 65,536 | רשתות ביתיות/משרדים קטנים |

כתובות מחוץ לטווחים אלו נחשבות **Public IP** ומנותבות ישירות באינטרנט.

## חישוב Subnet - שיטת ה-CIDR

טבלת המרה מלאה בין CIDR, Subnet Mask, ומספר הכתובות:

| CIDR | Subnet Mask | מספר כתובות כולל | מספר Hosts שמישים |
|---|---|---|---|
| /24 | 255.255.255.0 | 256 | 254 |
| /25 | 255.255.255.128 | 128 | 126 |
| /26 | 255.255.255.192 | 64 | 62 |
| /27 | 255.255.255.224 | 32 | 30 |
| /28 | 255.255.255.240 | 16 | 14 |
| /29 | 255.255.255.248 | 8 | 6 |
| /30 | 255.255.255.252 | 4 | 2 |

**נוסחה:** מספר כתובות כולל = 2^(32-CIDR). מספר Hosts שמישים = 2^(32-CIDR) - 2 (מפחיתים את כתובת הרשת וכתובת ה-Broadcast).

### דוגמת חישוב מעשית 1: חלוקת רשת /24 לתת-רשתות /26

נניח שקיבלנו את הרשת `192.168.10.0/24` וצריך לחלק אותה ל-4 תת-רשתות שוות (למשל 4 מחלקות במשרד):

```
רשת מקורית: 192.168.10.0/24  (256 כתובות)
דרישה: 4 subnets → נלווה 2 סיביות נוספות ל-Network (2^2=4)
מסכה חדשה: /24 + 2 = /26  (255.255.255.192)

Subnet 1: 192.168.10.0/26    (Hosts: .1   - .62,   Broadcast: .63)
Subnet 2: 192.168.10.64/26   (Hosts: .65  - .126,  Broadcast: .127)
Subnet 3: 192.168.10.128/26  (Hosts: .129 - .190,  Broadcast: .191)
Subnet 4: 192.168.10.192/26  (Hosts: .193 - .254,  Broadcast: .255)
```

### דוגמת חישוב מעשית 2: VLSM (Variable Length Subnet Mask) לדרישות שונות

נניח שיש 3 מחלקות בגדלים שונים: מחלקה A (50 מחשבים), מחלקה B (20 מחשבים), מחלקה C (10 מחשבים). ברשת `10.0.0.0/24`:

```
מחלקה A - צריך 50 hosts → /26 מספק 62 hosts   → 10.0.0.0/26   (10.0.0.1 - 10.0.0.62)
מחלקה B - צריך 20 hosts → /27 מספק 30 hosts   → 10.0.0.64/27  (10.0.0.65 - 10.0.0.94)
מחלקה C - צריך 10 hosts → /28 מספק 14 hosts   → 10.0.0.96/28  (10.0.0.97 - 10.0.0.110)
```

**היתרון של VLSM:** ניצול יעיל של מרחב הכתובות במקום להקצות /24 שלם (256 כתובות) לכל מחלקה גם אם היא צריכה רק 10.

### חישוב מהיר - "שיטת המספר המאגי" (Magic Number)

```
CIDR /27 → Subnet Mask 255.255.255.224
המספר המאגי = 256 - 224 = 32

כתובת: 192.168.1.75/27
Subnet-ים אפשריים בקפיצות של 32:
192.168.1.0, 192.168.1.32, 192.168.1.64, 192.168.1.96 ...

75 נמצא בין 64 ל-96 → הרשת של הכתובת: 192.168.1.64/27
טווח Hosts: 192.168.1.65 - 192.168.1.94
Broadcast: 192.168.1.95
```

## IPv6 - מבט מבוא

IPv6 משתמש בכתובות בנות 128 סיביות (במקום 32 ב-IPv4), מוצג בפורמט הקסדצימלי מחולק ל-8 קבוצות:

```
כתובת מלאה:  2001:0db8:0000:0000:0000:ff00:0042:8329
כתובת מקוצרת: 2001:db8::ff00:42:8329
```

כללי קיצור: אפסים מובילים בכל קבוצה ניתן להשמיט, ורצף אחד של קבוצות אפסים ניתן להחליף ב-`::` (פעם אחת בלבד בכתובת).

| סוג כתובת IPv6 | טווח | מקביל ל-IPv4 |
|---|---|---|
| Link-Local | `fe80::/10` | APIPA (169.254.x.x) |
| Unique Local (פרטי) | `fc00::/7` | RFC 1918 |
| Global Unicast (ציבורי) | `2000::/3` | Public IP |
| Loopback | `::1` | 127.0.0.1 |

## פקודות מעשיות לבדיקה וחישוב

```bash
# הצגת כתובות IP וממשקי הרשת
ip addr show                    # לינוקס
ipconfig                        # Windows

# בדיקת חישוב subnet עם ipcalc (לינוקס)
ipcalc 192.168.10.75/26
```

פלט לדוגמה מ-`ipcalc`:

```
Address:   192.168.10.75        11000000.10101000.00001010.01 001011
Netmask:   255.255.255.192 = 26 11111111.11111111.11111111.11 000000
Wildcard:  0.0.0.63              00000000.00000000.00000000.00 111111
=>
Network:   192.168.10.64/26     11000000.10101000.00001010.01 000000
HostMin:   192.168.10.65        11000000.10101000.00001010.01 000001
HostMax:   192.168.10.126       11000000.10101000.00001010.01 111110
Broadcast: 192.168.10.127       11000000.10101000.00001010.01 111111
Hosts/Net: 62
```

```bash
# בדיקת חיבור IPv6
ping6 2001:4860:4860::8888      # Google Public DNS IPv6
ping -6 2001:4860:4860::8888    # Windows
```

## טיפים וטריקים

1. **תרגלו חישובי Subnet בראש** — למדו את טבלת ה-CIDR עד /30 בעל פה, זו שאלה קבועה בראיונות עבודה.
2. **זכרו את הנוסחה** — Hosts שמישים = 2^(32-CIDR) - 2. אל תשכחו את ה-"-2" (Network + Broadcast).
3. **VLSM חוסך כתובות** — תמיד התאימו את גודל ה-Subnet לצורך בפועל, במיוחד בסביבות Cloud שבהן VPC/Subnet sizing משפיע ישירות על עלויות ותכנון.
4. **השתמשו בכלי אונליין לאימות** — כלים כמו `ipcalc` (CLI) או מחשבוני Subnet מקוונים מצוינים לאימות חישוב ידני.
5. **בענן (AWS/Azure/GCP)**, כתובת ה-Network וה-Broadcast של כל Subnet שמורות (ולעיתים גם עוד 2-3 כתובות למטרות פנימיות), כך שמספר ה-Hosts השמיש בפועל קטן מהחישוב התיאורטי הרגיל.
