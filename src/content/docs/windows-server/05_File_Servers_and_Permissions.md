# מדריך 5: שירותי קבצים, NTFS, Share ו-DFS 📁

## מבוא
ניהול שרתי קבצים ומידע ארגוני הוא אחד התפקידים המרכזיים של מנהל רשת. גישה לתיקיות מנוהלת דרך שני מנגנונים נפרדים שחייבים לעבוד יחד: **Share Permissions** (הרשאות רשת לשיתוף עצמו) ו-**NTFS Permissions** (הרשאות מערכת הקבצים על הדיסק). בנוסף, משתמשים בארגונים גדולים ב-DFS לניהול נוח של תיקיות רשת.

## מושגים והרשאות
*   **Share Permissions:** ההרשאות המסופקות כשניגשים לתיקייה מרחוק דרך נתיב רשת (UNC Path: `\\Server\Share`). מציעות רמות פשוטות: Full Control, Change, Read.
*   **NTFS Permissions:** ההרשאות החלות על התיקייה עצמה בדיסק הקשיח. הרבה יותר מפורטות: Modify, Write, Read & Execute וכו'. חלות גם כאשר המשתמש יושב ישירות על השרת.
*   **חוק ברזל:** בעת גישה מרחוק לתיקייה משותפת, גם הרשאות ה-Share וגם הרשאות ה-NTFS נבדקות. **ההרשאה המגבילה ביותר (Most Restrictive) היא זו שתנצח!** 
  *(לדוגמה: אם ב-Share יש לך Full Control אך ב-NTFS יש לך רק Read, אתה תוכל רק לקרוא את הקובץ).*
*   **DFS (Distributed File System):** מחולק לשניים:
    *   **DFS-N (Namespaces):** יצירת שם וירטואלי קבוע לכל הרשת (למשל `\\corp.local\files`) שמאגד בתוכו תיקיות משרתים פיזיים שונים.
    *   **DFS-R (Replication):** רפליקציה (סנכרון) של קבצים בזמן אמת בין שני שרתי קבצים או יותר לצורך שרידות וביצועים (לדוגמה, סניף תל אביב וסניף ניו יורק).

## ניהול הרשאות מורכב (PowerShell & Command Line)
```cmd
:: שמירת גיבוי של כל הרשאות ה-NTFS בתיקייה (קריטי לפני שינויים גדולים!)
icacls C:\Finance /save C:\temp\Finance_Acl.txt /t /c

:: שחזור הרשאות מתוך הקובץ
icacls C:\ /restore C:\temp\Finance_Acl.txt

:: PowerShell: חילוץ הרשאות התיקייה
Get-Acl -Path "C:\HR_Data" | Format-List
```

## דוגמאות מפורטות לניהול שרת קבצים
**שיטת Best Practice לניהול הרשאות – מודל AGDLP:**
מיקרוסופט ממליצה על שיטה לסידור הרשאות כדי לא ללכת לאיבוד בעתיד:
1. **A (Account):** המשתמש, למשל ירון מהנהלת חשבונות.
2. **G (Global Group):** הכניסו את ירון לקבוצה ב-AD המשקפת את התפקיד שלו, למשל `Finance-Users-GG`.
3. **DL (Domain Local Group):** צרו קבוצה המשקפת את המשאב וההרשאה, למשל `FinanceFolder-Modify-DLG`.
4. **P (Permissions):** תנו את ההרשאות על תיקיית הכספים (NTFS Modify) *אך ורק* לקבוצה `FinanceFolder-Modify-DLG`.
5. לבסוף, הוסיפו את קבוצת ה-Global (G) לתוך קבוצת ה-Domain Local (DL).
*מדוע?* אם יצטרף עובד חדש, פשוט נוסיף אותו ל-Finance-Users, והוא אוטומטית יקבל גישה. אם נרצה לשנות מי יכול לכתוב לתיקייה, נשנה פעם אחת את הגדרות התיקייה, הכל נשאר דינמי וברור.

## טיפים וטריקים 💡
*   **ABE (Access-Based Enumeration):** תכונה שחובה להפעיל על תיקיות שיתוף. היא מסתירה מיוזרים תיקיות שאין להם הרשאות אליהן. משתמש ייכנס לכונן הרשת ויראה *רק* את מה שמותר לו לראות. כך הוא לא יידע בכלל שקיימת תיקיית משכורות אם אין לו גישה אליה. מופעל דרך ה-Server Manager -> File and Storage Services.
*   **הרשאות Share מומלצות:** Best Practice פשוט — תנו ב-Share תמיד ל-`Everyone = Full Control` (או לקבוצת משתמשים רחבה), ונהלו את האבטחה האמיתית והמיקרו-הגדרות *רק* דרך ה-NTFS Permissions. כך לא תצטרכו לנהל הרשאות בשני מקומות במקביל.

## שאלות ראיון עבודה 🎯
1. **שאלה:** משתמש מעתיק קובץ מתיקייה א' לתיקייה ב' באותו כונן (Volume). מה קורה להרשאות הקובץ?
   *תשובה:* בהעתקה (Copy), הקובץ יוצר ישות חדשה ולכן *יורש* את ההרשאות של תיקיית היעד (תיקייה ב').
2. **שאלה:** ומה יקרה אם הוא *יגזור וידביק* (Move) את אותו הקובץ באותו כונן?
   *תשובה:* בפעולת Move על אותו כונן, הקובץ לא באמת נכתב מחדש אלא רק מצביע המיקום שלו משתנה בטבלת ה-MFT. לכן הקובץ *שומר* על ההרשאות המקוריות שלו מתיקייה א'. (זה אחד הגורמים הנפוצים ביותר לתקלות הרשאה!).
3. **שאלה:** מהו FSRM (File Server Resource Manager)?
   *תשובה:* תכונה בשרת המאפשרת הגדרת מכסות (Quotas) על תיקיות למניעת התמלאות דיסקים, וסינון קבצים (File Screening) המונע ממשתמשים לשמור קבצי MP3, AVI או קבצי תוכנת כופר בשרת הארגוני.
