## מבוא
שרת שפועל בצורה תקינה אך לא מאובטח או לא מגובה, מהווה פצצת זמן עבור הארגון. מדריך זה מתמקד באסטרטגיות האבטחה הבסיסיות והמתקדמות ב-Windows Server, ניטור לוגים, וכמובן התאוששות מאסון (Disaster Recovery).

## ניהול אבטחה מתקדם בארגון
*   **LAPS (Local Administrator Password Solution):** כל מחשב ושרת בווינדוס מגיע עם משתמש Local Administrator פנימי. האקרים מנצלים זאת על ידי גניבת הסיסמה ממחשב אחד (למשל משרד הקבלה) והתחברות לשאר השרתים. LAPS מסנכרן סיסמה אקראית חזקה (כמו `&Gf62!sL`) באופן אוטומטי, ושומר אותה מאובטחת בתוך ה-Active Directory.
*   **WSUS (Windows Server Update Services):** שרת עדכונים פנימי. במקום שכל השרתים בארגון יורידו עדכונים מהאינטרנט ויעשו הפעלה מחדש מתי שבא להם, מקימים שרת WSUS שמושך עדכונים פעם אחת ממיקרוסופט. מנהל הרשת יכול לאשר אילו עדכונים יתוקנו ומתי (ניהול Patching מבוקר).
*   **Event Viewer (מציג האירועים):** המערכת ב-Windows לתיעוד אירועים, שגיאות, והתראות אבטחה. האירועים הקריטיים נמצאים ב-System, Security, ו-Application.

## מנגנוני גיבוי והתאוששות (Windows Server Backup)
Windows כולל כלי מובנה ואמין לגיבוי הקרוי Windows Server Backup (דורש התקנה כ-Feature). הגיבויים החשובים:
1. **Full Backup / Bare Metal Recovery:** גיבוי מושלם המאפשר לשחזר שרת שקרס לחלוטין לשרת חומרה חדש לגמרי, כולל מערכת ההפעלה והכל.
2. **System State:** גיבוי קריטי ל-Domain Controllers. מגבה את קבצי התצורה של השרת, ה-Registry ומסד הנתונים של ה-Active Directory.

### פקודות שימושיות וגיבוי ב-CMD/PowerShell
```cmd
:: הפעלת גיבוי System State מיידי לכונן E (משמש כגיבוי דחוף לפני שינויים מסוכנים)
wbadmin start systemstatebackup -backupTarget:E:

:: PowerShell: חיפוש לוגים ב-Event Viewer (חיפוש כל הכניסות השגויות במערכת - Event ID 4625)
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625} | Select-Object TimeCreated, Message | Format-Table -AutoSize
```

## דוגמאות מפורטות לגיבוי יעיל
**מודל הגיבוי: הבדל בין Full, Incremental, ו-Differential**
כאשר מגדירים תוכנת גיבוי ארגונית (כמו Veeam או כלי מובנה):
*   **Full Backup:** כל הנתונים מגובים בכל פעם. כבד מאוד, איטי ולוקח הרבה מקום אחסון, אבל השחזור הוא המהיר והקל ביותר (קובץ אחד).
*   **Incremental (תוספתי):** הגיבוי הראשון הוא Full. למחרת הגיבוי שומר *רק את מה שהשתנה מאתמול*. השחזור איטי (צריך לחבר את ה-Full ואת כל ימי השינויים), אך תהליך הגיבוי הלילי מאוד מהיר וחסכוני במקום.
*   **Differential (דיפרנציאלי):** הגיבוי הראשון הוא Full. ביום שני הוא מגבה שינויים מאז ה-Full. ביום שלישי הוא מגבה *שוב את כל השינויים מאז ה-Full*. זמן הגיבוי הולך ומתארך במהלך השבוע, אך תהליך השחזור דורש רק שני קבצים (ה-Full + הגיבוי האחרון).

## טיפים וטריקים 💡
*   **חוק 3-2-1:** זהו חוק הזהב בגיבויים ארגוניים.
    * **3** עותקים של המידע (המקור + 2 גיבויים).
    * **2** סוגי מדיות שונות (למשל כונן NAS מקומי ובנוסף קלטות טייפ או דיסקים חיצוניים).
    * **1** עותק מחוץ לאתר הפיזי (Offsite - ענן או כספת בסניף אחר). אם המשרד נשרף או הוצף, הגיבוי בארון השרתים לא יעזור.
*   **Test your backups!** גיבוי שלא ניסיתם לשחזר בעזרתו סביבת מעבדה - הוא גיבוי שלא קיים. חברות רבות מגלות בזמן אירוע כופר (Ransomware) שהגיבוי שלהם נכשל כבר שנה והם פשוט לא בדקו.

## שאלות ראיון עבודה 🎯
1. **שאלה:** ארגון נפגע מתוכנת כופר, השרתים והגיבויים על ה-NAS המקומי הוצפנו כולם. איזה מנגנון היה מונע את הצפנת הגיבויים?
   *תשובה:* הוספת גיבוי Air-gapped או Immutable storage (אחסון שאינו ניתן לשינוי גם על ידי אדמין, או ניתוק פיזי של מדיות גיבוי כמו קלטות). כמו כן שמירת עותק מנותק לחלוטין ברשת אחרת (Offsite).
2. **שאלה:** מהו Event ID 4624 ומהו Event ID 4625?
   *תשובה:* ביומני האבטחה (Security Logs), 4624 מעיד על התחברות מוצלחת (Logon Success) של משתמש למערכת. אירוע 4625 מעיד על כשל בהתחברות (Logon Failure) – למשל סיסמה שגויה. כמות חריגה של 4625 עשויה להעיד על התקפת Brute-Force.
3. **שאלה:** מה תפקידו של ה-BitLocker בשרתים?
   *תשובה:* הצפנת תוכן הדיסקים ברמת החומרה. מונע מצב שבו תוקף נכנס פיזית לחוות השרתים (או מרכז מחשבים), מוציא את הדיסק הקשיח מהשרת, מחבר למחשב אחר וקורא את הקבצים או את קבצי הסיסמאות של ה-AD (קובץ ה-NTDS.dit). ללא סיסמת הביטלוקר הקובץ קריפטוגרפי ובלתי קריא.
