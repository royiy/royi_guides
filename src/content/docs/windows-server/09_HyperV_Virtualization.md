## מבוא
Hyper-V הוא מנגנון הווירטואליזציה (Hypervisor) המובנה של Windows Server. הוא מאפשר לשרת הפיזי (ה-Host) להריץ מספר שרתים דמיוניים / מכונות וירטואליות (VM - Virtual Machines) שמתחלקים במשאבי החומרה (CPU, זיכרון, דיסקים ורשת) באופן מבודד לחלוטין.
Hyper-V בשרת נחשב **Type 1 Hypervisor** (הנקרא גם Bare-Metal), כלומר שכבת הניהול שלו מתיישבת ממש מתחת למערכת ההפעלה כדי להשיג ביצועי חומרה מקסימליים.

## מושגים קריטיים בהגדרת מכונות ווירטואליות
*   **Generation 1 לעומת Generation 2:** 
    *   **Gen 1:** תומך במערכות הפעלה ישנות. משתמש ב-BIOS ומדמה חומרת לגאסי (כמו כרטיסי רשת ישנים).
    *   **Gen 2:** חובה עבור מערכות חדישות. מבוסס UEFI, מאובטח יותר (Secure Boot), זמני אתחול מהירים בהרבה, תמיכה בדיסקים גדולים מהרגע הראשון והתקנות רשת מתקדמות יותר.
*   **סוגי דיסקים קשיחים (VHDX):**
    *   **Fixed Size:** קובץ שמיד לוקח את כל המקום שהוקצה לו בדיסק המארח. מהיר יותר.
    *   **Dynamically Expanding:** מתחיל קטן וגדל בהדרגה ככל ששומרים עליו מידע במכונה הווירטואלית. חוסך מקום בדיסק אך מעט יותר איטי.

## פקודות וירטואליזציה
ניהול Hyper-V בעזרת פאוורשל הוא מהיר במיוחד, בייחוד כשרוצים להקים מעבדת שרתים בלחיצת כפתור:
```powershell
# יצירת מכונה חדשה מסוג Gen 2 עם זיכרון 4GB ודיסק וירטואלי של 50GB
New-VM -Name "SRV-FILE-02" -MemoryStartupBytes 4GB -Generation 2 -NewVHDPath "D:\HyperV\Virtual Hard Disks\SRV-FILE-02.vhdx" -NewVHDSizeBytes 50GB

# חיבור המכונה לווירטואל-סוויץ' (Virtual Switch) הרשתי
Connect-VMNetworkAdapter -VMName "SRV-FILE-02" -SwitchName "Ext-Switch-Production"

# הפעלת המכונה
Start-VM -Name "SRV-FILE-02"

# יצירת תמונת מצב (Checkpoint) לפני ביצוע עדכון מסוכן
Checkpoint-VM -Name "SRV-FILE-02" -SnapshotName "Pre-Windows-Update"
```

## דוגמאות מפורטות לניהול רשת וירטואלית
**תרחיש: בחירת מתג וירטואלי (Virtual Switch)**
ה-Hyper-V מציע 3 סוגים של מתגים וירטואליים. הכרתם חשובה מאין כמותה:
1. **External (חיצוני):** המתג מחובר לכרטיס הרשת הפיזי של השרת. המכונות הווירטואליות יכולות לגשת לרשת הארגונית האמיתית ולאינטרנט. המכונות יקבלו כתובת IP משרת ה-DHCP של הארגון.
2. **Internal (פנימי):** המכונות הווירטואליות יכולות לדבר אחת עם השנייה, **וגם** לתקשר עם השרת הפיזי (ה-Host). אך הן אינן יוצאות החוצה לרשת הארגונית (מעולה למעבדות מבודדות שהאדמין עדיין רוצה לנהל מהמחשב שלו).
3. **Private (פרטי):** רשת סגורה לחלוטין. המכונות מדברות *רק* אחת עם השנייה. השרת המארח לא יכול להתחבר אליהן. משמש לרוב לאשכולות (Clusters) או בקרת סביבות מנותקות.

## טיפים וטריקים 💡
*   **Checkpoints הם לא גיבוי!** תכונת ה-Checkpoint (בעבר Snapshot) מאפשרת להקפיא את המכונה ברגע נתון. זה מצוין לפני עדכונים, אך אסור להשאיר Checkpoint פתוח לאורך ימים או שבועות. המערכת מייצרת קובץ AVHDX (דיסק שינויים) שגדל ללא שליטה, פוגע אנושות בביצועים ועלול לכלות את שטח הדיסק ולרסק את השרת המארח. מרגו (Merge) צ'קפוינטים מיד עם סיום הניסוי.
*   **Dynamic Memory (זיכרון דינמי):** הפעילו זיכרון דינמי אם אתם רוצים שהמכונה תיקח מהשרת הפיזי רק את ה-RAM שהיא באמת צריכה ברגע הנתון. הגדירו לה מינימום ומקסימום כדי שלא תחנק את כל השרת.

## שאלות ראיון עבודה 🎯
1. **שאלה:** מה ההבדל בין Type 1 ל-Type 2 Hypervisor? 
   *תשובה:* Hyper-V ב-Windows Server ו-VMware ESXi הם Type 1 שיושבים ישירות על החומרה. לעומתם, VirtualBox או VMware Workstation במחשב הביתי הם Type 2 - אפליקציות שרצות מעל מערכת ההפעלה הקיימת ולכן איטיות וצרכניות יותר.
2. **שאלה:** שרת וירטואלי של מסד נתונים עובד לאט. אני מגלה שמוגדר לו Checkpoint לפני שנה שמעולם לא נמחק. למה זה קורה?
   *תשובה:* בגלל שהצ'קפוינט פתוח שנה, השרת כותב נתונים חדשים רק לקובץ השינויים הזמני (Differencing Disk). הוא צריך לחשב שינויים בין הדיסק המקורי לדיסק הזמני כל פעם שמתבצעת קריאה. זה מפרק את ה-IOPS של הדיסק הפיזי וגורם להאטה קריטית.
3. **שאלה:** מהו Live Migration?
   *תשובה:* היכולת להעביר מכונה וירטואלית דולקת ועובדת משרת Hyper-V פיזי אחד לשרת פיזי אחר מבלי שאף משתמש ירגיש נתק (Downtime).
