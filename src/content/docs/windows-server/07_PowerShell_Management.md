# מדריך 7: ניהול ואוטומציה של שרתים באמצעות PowerShell ⚡

## מבוא
PowerShell היא כבר מזמן לא כלי "נחמד שיהיה", היא כלי חובה! היא מסגרת ניהול תצורה ואוטומציה מבוססת עצמים (Object-Oriented), להבדיל מסביבות לינוקס (כמו Bash) שמחזירות טקסט נקי. כל פקודה (הנקראת Cmdlet) מחזירה אובייקט בעל מאפיינים ופעולות, מה שמאפשר שרשור פקודות עוצמתי.

## מבנה ומושגי יסוד
*   **Cmdlets (קומנדלטים):** בנויים בתצורת `Verb-Noun` (פועל-שם עצם). למשל: `Get-Process`, `Stop-Service`, `New-Item`.
*   **Pipeline (הצינור - `|`):** מאפשר לקחת תוצאה של פקודה אחת, ולהעביר אותה הלאה לפקודה הבאה. למשל, למצוא משתמשים שהתנתקו ולמחוק אותם בשורה אחת.
*   **Execution Policy:** מנגנון האבטחה של פאוורשל שקובע אם מותר להריץ סקריפטים (קובצי `.ps1`) במערכת. 

## פקודות ומושגים - בסיסי ומתקדם
```powershell
# למידת פקודות - המקבילה של 'man' בלינוקס. מביא גם דוגמאות קוד!
Get-Help Get-Process -Examples

# למצוא פקודה לפי מילת מפתח (נניח שלא זכרנו איך משנים כתובת IP)
Get-Command *IPAddress*

# Pipeline עוצמתי: איתור שירותים מסוג מסוים, סינונם לפי מצב, וכיבויים
Get-Service | Where-Object {$_.Status -eq "Running" -and $_.Name -like "*spooler*"} | Stop-Service

# PowerShell Remoting: פתיחת טרמינל מלא לשרת מרוחק
Enter-PSSession -ComputerName "SRV-WEB01"
```

## דוגמאות מפורטות לניהול ואוטומציה
**תרחיש: הרצת פקודה אחת על עשרות שרתי הארגון במקביל.**
נניח שיש לנו 3 שרתי Web (IIS) ואנחנו רוצים להפעיל מחדש את השירות בכולם בבת אחת, ללא צורך להתחבר ב-RDP לכל אחד.
נשתמש ב- `Invoke-Command` שמתחבר אליהם ברקע (עובד מעל WinRM / Port 5985):

```powershell
$servers = @("Web1", "Web2", "Web3")
Invoke-Command -ComputerName $servers -ScriptBlock {
    Restart-Service -Name W3SVC -Force
    Write-Output "IIS restarted on $env:COMPUTERNAME"
}
```
הפקודה תשלח את בלוק הקוד לכל שרת, תבצע אותו, ותחזיר את התוצאה למסך שלנו בצורה מסודרת.

## טיפים וטריקים 💡
*   **הגנת WhatIf:** בכל פעם שאתם מריצים פקודה בעלת פוטנציאל הרס (מחיקת משתמשים, כיבוי מחשבים, הסרת קבצים), הוסיפו בסוף הפקודה `-WhatIf`. הפאוורשל לא יבצע את הפקודה אלא רק ידפיס למסך "מה היה קורה אילו הרצתי אותה". כך תמנעו מטעויות פטאליות (כמו מחיקת כל תיקיית ה-AD במקום משתמש בודד).
*   **ISE לעומת VS Code:** ה-PowerShell ISE המובנה בווינדוס כבר לא מפותח על ידי מיקרוסופט. מומלץ להתקין את **Visual Studio Code** יחד עם תוסף ה-PowerShell — היא מספקת חוויית כתיבת סקריפטים מודרנית עם השלמה אוטומטית, GIT ותמיכה בגרסאות PowerShell 7+.

## שאלות ראיון עבודה 🎯
1. **שאלה:** מה משמעות המשתנה `$_` או `$PSItem` ב-Pipeline?
   *תשובה:* הוא מייצג את האובייקט *הנוכחי* שעובר ברגע זה בצנרת. בתוך לולאה או בסינון (`Where-Object`), המערכת עוברת על הרשימה אובייקט אחר אובייקט. `$_` אומר "קח את האובייקט שאני מסתכל עליו עכשיו, ותבדוק את התכונות שלו".
2. **שאלה:** לא מצליח להריץ סקריפט מותאם אישית שכתבתי, אני מקבל שגיאה אדומה ש"הפעלת סקריפטים מושבתת". מה עושים?
   *תשובה:* ה-Execution Policy מוגדר כברירת מחדל ל-Restricted (לא מאפשר הרצת סקריפטים כלל). יש להריץ את הפקודה כמנהל: `Set-ExecutionPolicy RemoteSigned` שיאפשר הרצת סקריפטים מקומיים, וסקריפטים מהאינטרנט רק אם יש להם חתימה דיגיטלית.
3. **שאלה:** מה ההבדל בין `Enter-PSSession` ל- `Invoke-Command`?
   *תשובה:* `Enter-PSSession` פותח סשן אינטראקטיבי שבו אתה מקליד פקודות בלייב מול שרת אחד. `Invoke-Command` מריץ בלוק קוד ברקע, יכול לרוץ נגד עשרות שרתים במקביל, ומחזיר את התוצאות לשרת המקומי ללא ממשק אינטראקטיבי.
