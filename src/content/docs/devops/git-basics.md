## מה זה Git?

Git הוא מערכת לניהול גרסאות - "היסטוריית שינויים" חכמה לפרויקט. כל פעם שאתה מרוצה משלב מסוים בעבודה, אתה שומר "תמונת מצב" (commit), ו-Git זוכר בדיוק מה השתנה, מתי, ומי עשה את זה. זה מאפשר לחזור אחורה, להשוות בין גרסאות, ולעבוד בבטחה גם אם משהו נשבר.

**GitHub** הוא שירות אונליין שמאחסן את ההיסטוריה הזו בענן - לגיבוי, לגישה מכל מחשב, ולחיבור לשירותי אירוח שמפרסמים אתרים אוטומטית.

## דרישות מוקדמות

- Git מותקן על המחשב ([git-scm.com](https://git-scm.com))
- חשבון GitHub
- פרויקט מקומי שכבר מכיל קבצים

## הגדרה חד-פעמית

לפני ה-commit הראשון אי פעם על מחשב חדש, צריך לומר ל-Git מי אתה:

```
git config --global user.email "your@email.com"
git config --global user.name "Your Name"
```

הפעולה הזו נדרשת פעם אחת בלבד למחשב, ולא צריך לחזור עליה בכל פרויקט.

## הפקודות שלב אחר שלב

### 1. `git add .`

מסמן שקבצים ששינית (או חדשים) עומדים לשמירה בשלב הבא. הנקודה אומרת ל-Git "שים לב לכל הקבצים בתיקייה". השינוי עדיין לא נשמר בפועל בשלב הזה - רק מסומן.

### 2. `git commit -m "תיאור"`

שומר בפועל את תמונת המצב שסומנה ב-`add`, יחד עם הודעה שמתארת מה השתנה. ההודעה עוזרת לך בעתיד להבין מה קרה בנקודה הזו בלי לפתוח כל קובץ.

### 3. `git branch -M main`

משנה את שם הענף (branch) הראשי ל-`main`. ענף הוא קו נפרד של עבודה - למשל אפשר לנסות שינוי מסוכן בענף נפרד בלי לפגוע בגרסה החיה. למתחילים, מספיק לעבוד עם ענף אחד בשם `main`.

### 4. `git remote add origin <כתובת>`

מחבר את הפרויקט המקומי לכתובת הריפו ב-GitHub, וקורא לחיבור הזה "origin" (שם מוסכם). נעשה פעם אחת לכל פרויקט.

### 5. `git push -u origin main`

מעלה בפועל את ה-commits המקומיים לענף `main` שב-GitHub. הדגל `-u` אומר ל-Git לזכור את החיבור בין הענף המקומי לענף `origin`, כך שבפעמים הבאות אפשר פשוט לכתוב `git push`.

## תהליך העבודה השוטף

אחרי שהחיבור הראשוני מוגדר, כל פעם שמשנים משהו בפרויקט מספיקות שלוש פקודות:

```
git add .
git commit -m "תיאור קצר של מה ששיניתי"
git push
```

בלי `branch -M` ובלי `remote add` - אלה כבר מוגדרים מהפעם הראשונה.

## טיפ שימושי: `git status`

אפשר להריץ בכל שלב כדי לראות מה המצב עכשיו - אילו קבצים השתנו, מה כבר סומן ל-`add`, ומה עדיין לא. שווה להריץ אותה כל פעם שלא בטוחים מה קורה.

## סיכום

Git עובד במחזור פשוט: משנים קבצים → `git add` מסמן אותם → `git commit` שומר תמונת מצב מקומית → `git push` מעלה אותה ל-GitHub. ההגדרה הראשונית (`config`, `branch -M`, `remote add`) נדרשת פעם אחת בלבד, ומכאן והלאה כל עדכון הוא שלוש שורות.
