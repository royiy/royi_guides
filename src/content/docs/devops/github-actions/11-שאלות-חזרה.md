שאלות חזרה אינטראקטיביות על כל מה שלמדתם לאורך מדריכי ה-GitHub Actions (מבוא ויסודות, תחביר Workflow וטריגרים, Jobs/Steps/Runners, Secrets ומשתני סביבה, Actions מוכנים מה-Marketplace, Matrix Strategy, בניית Pipeline CI/CD מלא, Docker ו-Containers, יצירת Custom Actions, ואבטחה/Debugging). בחרו תשובה בכל שאלה ותקבלו מיד משוב האם היא נכונה, יחד עם הסבר.

<div id="quiz-score" class="quiz-score">ענית נכון על 0 מתוך 10</div>

<div class="quiz-card" data-answer="ב">
  <p class="quiz-question"><strong>1. מה ההבדל בין <code>run</code> ל-<code>uses</code> בתוך step ב-GitHub Actions?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. <code>run</code> מפעיל Action מוכן, ו-<code>uses</code> מריץ פקודת shell</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. <code>run</code> מריץ פקודת shell ישירה, ואילו <code>uses</code> מפעיל Action מוכן (מ-Marketplace, מריפו אחר, או local)</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. אין הבדל, שתי מילות המפתח שקולות לגמרי</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. <code>run</code> עובד רק על self-hosted runners, ו-<code>uses</code> רק על GitHub-hosted</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> כל step הוא אחד משני סוגים: <code>run</code> מריץ פקודת shell ישירה, ו-<code>uses</code> מפעיל Action קיים - בין אם מה-Marketplace, מריפו אחר, או Action מקומי כמו <code>./.github/actions/my-action</code>.</div>
</div>

<div class="quiz-card" data-answer="ב">
  <p class="quiz-question"><strong>2. מה ההבדל המרכזי בין הטריגר <code>pull_request</code> לטריגר <code>pull_request_target</code>?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. אין הבדל מעשי בין השניים</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. <code>pull_request</code> רץ בהקשר ממוזג עם הרשאות מוגבלות (במיוחד מ-fork, ללא גישה ל-secrets), ואילו <code>pull_request_target</code> רץ עם הרשאות מלאות של הענף הבסיסי גם על PR מ-fork</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. <code>pull_request_target</code> מיועד לשימוש רק בריפוזיטוריז פרטיים</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. <code>pull_request</code> מופעל רק פעם ביום לפי לוח זמנים (cron)</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> ההבדל הזה קריטי לאבטחה: <code>pull_request_target</code> מריץ עם הרשאות מלאות (כולל secrets) של הענף הבסיסי גם כשה-PR מגיע מ-fork חיצוני, ולכן שילוב שלו עם checkout של קוד ה-PR עצמו מסוכן ועלול להריץ קוד לא מהימן עם הרשאות גבוהות.</div>
</div>

<div class="quiz-card" data-answer="א">
  <p class="quiz-question"><strong>3. מהו התחביר העדכני להגדרת output מתוך step, שהחליף את הפורמט הישן <code>::set-output</code> מטעמי אבטחה?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. כתיבה לקובץ המיוחד <code>$GITHUB_OUTPUT</code> בפורמט <code>key=value</code></button>
    <button class="quiz-option" type="button" data-choice="ב">ב. שימוש בפקודת <code>export</code> רגילה של bash</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. הגדרת <code>outputs:</code> ברמת ה-workflow בלבד, בלי צורך ב-step</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. שמירת הערך בקובץ <code>$GITHUB_ENV</code></button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> כותבים ל-<code>$GITHUB_OUTPUT</code> (למשל <code>echo "version=1.4.2" &gt;&gt; "$GITHUB_OUTPUT"</code>) וקוראים דרך <code>steps.&lt;id&gt;.outputs.&lt;name&gt;</code>. זה שונה מ-<code>$GITHUB_ENV</code>, שמיועד למשתני סביבה לכל שאר שלבי ה-job ולא ל-outputs שמועברים בין jobs.</div>
</div>

<div class="quiz-card" data-answer="ב">
  <p class="quiz-question"><strong>4. מה ההבדל העיקרי בין Secret ל-Variable ב-GitHub Actions?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. Secret זמין תמיד גם ב-PR מ-fork, ואילו Variable לא זמין</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. Secret מיועד לערכים רגישים, מוצפן ומוסתר בלוגים (<code>***</code>); Variable מיועד לערכים לא רגישים, נשמר כטקסט רגיל וניגש דרך <code>${{ vars.NAME }}</code></button>
    <button class="quiz-option" type="button" data-choice="ג">ג. שניהם זהים לחלוטין מבחינת אבטחה וחשיפה בלוגים</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. Variable אפשר להגדיר רק ברמת Organization, ואילו Secret רק ברמת Repository</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> הכלל הבסיסי: כל דבר שלא רוצים שמישהו יראה בלוג הוא secret (ניגש עם <code>secrets.NAME</code>), וכל דבר אחר שהוא קונפיגורציה רגילה הוא variable (ניגש עם <code>vars.NAME</code>). שני הסוגים ניתנים להגדרה בשלוש רמות: Repository, Environment ו-Organization.</div>
</div>

<div class="quiz-card" data-answer="ב">
  <p class="quiz-question"><strong>5. למה מומלץ לנעול Action כמו <code>actions/checkout</code> לגרסה ספציפית (תג כמו <code>@v4</code>, ואפילו יותר טוב - commit SHA מלא) ולא להשתמש ב-<code>@main</code>?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. כי <code>@main</code> תמיד איטי משמעותית להורדה</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. כי <code>@main</code> יכול להשתנות בכל רגע, כולל שינויים בלתי צפויים או פורצים, בעוד שגרסה נעולה מבטיחה יציבות וחזרתיות (reproducibility)</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. כי GitHub חוסם טכנית שימוש ב-<code>@main</code> ב-workflows ציבוריים</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. אין הבדל אמיתי, זו רק המלצת סגנון קוד ללא השלכה מעשית</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> נעילת Action ל-<code>uses</code> רץ עם קוד של צד שלישי, לעיתים עם גישה ל-secrets. נעילה לתג גרסה סבירה, אך הצמדה ל-commit SHA מלא היא הבטוחה ביותר כי היא immutable לחלוטין ומבטיחה שאותו קוד בדיוק ירוץ בכל פעם.</div>
</div>

<div class="quiz-card" data-answer="ב">
  <p class="quiz-question"><strong>6. מה קורה כברירת מחדל (<code>fail-fast: true</code>) כאשר קומבינציה אחת ב-matrix strategy נכשלת?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. רק אותה קומבינציה מסומנת ככישלון, ושאר הקומבינציות ממשיכות לרוץ עד הסוף</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. כל שאר הקומבינציות שעדיין רצות באותה מטריצה מבוטלות מיידית</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. כל ה-workflow כולו מתחיל לרוץ מחדש מאפס</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. המטריצה מתעדכנת אוטומטית ומדלגת על אותה קומבינציה בריצה הבאה בלבד</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> זו ברירת המחדל שחוסכת זמן ומשאבים, אך לפעמים לא רוצים בה - למשל אם רוצים לראות בדיוק אילו מערכות הפעלה נכשלות. במקרה כזה מגדירים <code>fail-fast: false</code> כדי שכל הקומבינציות ימשיכו לרוץ עד הסוף.</div>
</div>

<div class="quiz-card" data-answer="א">
  <p class="quiz-question"><strong>7. מה ההבדל בין Continuous Delivery ל-Continuous Deployment?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. ב-Continuous Delivery הקוד תמיד נמצא במצב "ניתן לפריסה" אך דורש אישור ידני; ב-Continuous Deployment הפריסה קורית אוטומטית לגמרי לאחר שכל הבדיקות עוברות, ללא התערבות אנושית</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. Continuous Deployment מתאים רק לצוותים קטנים, ו-Continuous Delivery רק לארגונים גדולים</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. Continuous Delivery כולל רק בדיקות unit, ו-Continuous Deployment כולל גם בדיקות integration</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. אין הבדל בין שני המונחים, הם מתארים בדיוק את אותו תהליך</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> שלושת עקרונות ה-CI/CD הם Continuous Integration (בנייה ובדיקות אוטומטיות לכל שינוי), Continuous Delivery (הקוד תמיד מוכן לפריסה אך יש אישור ידני), ו-Continuous Deployment (פריסה אוטומטית מלאה ללא התערבות אנושית לאחר שכל הבדיקות עוברות).</div>
</div>

</div>

<div class="quiz-card" data-answer="ב">
  <p class="quiz-question"><strong>9. מדוע חייבים לציין <code>shell:</code> במפורש בכל step מסוג <code>run</code> בתוך Composite Action, בניגוד ל-workflow רגיל?</strong></p>

    <button class="quiz-option" type="button" data-choice="ג">ג. זו הייתה דרישה שהוסרה כבר בגרסאות עדכניות של GitHub Actions</button>

(function () {
  function initQuiz() {
    var cards = document.querySelectorAll('.quiz-card');
    var scoreEl = document.getElementById('quiz-score');
    var resetAllBtn = document.getElementById('quiz-reset-all');

    function updateScore() {
      if (!scoreEl) return;
      var correctCount = document.querySelectorAll('.quiz-card--answered[data-was-correct="true"]').length;
      scoreEl.textContent = 'ענית נכון על ' + correctCount + ' מתוך ' + cards.length;
    }

    function answerCard(card, chosenBtn) {
      var correct = card.getAttribute('data-answer');
      var chosen = chosenBtn.getAttribute('data-choice');
      var isCorrect = chosen === correct;

      card.classList.add('quiz-card--answered');
      card.setAttribute('data-was-correct', isCorrect ? 'true' : 'false');

      var options = card.querySelectorAll('.quiz-option');
      options.forEach(function (opt) {
        opt.disabled = true;
        if (opt.getAttribute('data-choice') === correct) {
          opt.classList.add('quiz-option--correct');
        } else if (opt === chosenBtn) {
          opt.classList.add('quiz-option--incorrect');
        }
      });

      var result = card.querySelector('.quiz-result');
      if (result) {
        result.textContent = isCorrect ? '✅ נכון!' : '❌ לא נכון - התשובה הנכונה מסומנת בירוק.';
        result.classList.remove('quiz-result--correct', 'quiz-result--incorrect');
        result.classList.add(isCorrect ? 'quiz-result--correct' : 'quiz-result--incorrect');
      }

      updateScore();
    }

    function resetCard(card) {
      card.classList.remove('quiz-card--answered');
      card.removeAttribute('data-was-correct');
      var options = card.querySelectorAll('.quiz-option');
      options.forEach(function (opt) {
        opt.disabled = false;
        opt.classList.remove('quiz-option--correct', 'quiz-option--incorrect');
      });
      var result = card.querySelector('.quiz-result');
      if (result) {
        result.textContent = '';
        result.classList.remove('quiz-result--correct', 'quiz-result--incorrect');
      }
    }

    cards.forEach(function (card) {
      card.querySelectorAll('.quiz-option').forEach(function (btn) {
        btn.addEventListener('click', function () {
          if (card.classList.contains('quiz-card--answered')) return;
          answerCard(card, btn);
        });
      });
    });

    if (resetAllBtn) {
      resetAllBtn.addEventListener('click', function () {
        cards.forEach(resetCard);
        updateScore();
      });
    }

    updateScore();
  }

  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', initQuiz);
  } else {
    initQuiz();
  }
})();
</script>
