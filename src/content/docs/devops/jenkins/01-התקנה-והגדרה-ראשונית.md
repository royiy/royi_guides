## מבוא
Jenkins הוא שרת אוטומציה open-source שמשמש בעיקר ל-CI/CD (Continuous Integration / Continuous Delivery). הוא כתוב ב-Java ורץ כ-WAR file או כ-container. במדריך הזה נעבור על כל דרכי ההתקנה, ההגדרה הראשונית, ופתרון בעיות נפוצות.

## דרישות מקדימות
- Java 11 או Java 17 (Jenkins המודרני דורש JDK, לא רק JRE)
- לפחות 256MB RAM (מומלץ 4GB+ לסביבת עבודה אמיתית)
- 10GB פנויים בדיסק (למשתמשי plugins מרובים)
- גישה לאינטרנט (להורדת plugins)

## התקנה על Ubuntu/Debian (apt)

```bash
# הוספת מפתח GPG הרשמי
sudo wget -O /usr/share/keyrings/jenkins-keyring.asc \
  https://pkg.jenkins.io/debian-stable/jenkins.io-2023.key

# הוספת ה-repository
echo "deb [signed-by=/usr/share/keyrings/jenkins-keyring.asc]" \
  https://pkg.jenkins.io/debian-stable binary/ | sudo tee \
  /etc/apt/sources.list.d/jenkins.list > /dev/null

# עדכון והתקנה
sudo apt-get update
sudo apt-get install fontconfig openjdk-17-jre jenkins

# הפעלה
sudo systemctl enable jenkins
sudo systemctl start jenkins
sudo systemctl status jenkins
```

## התקנה עם Docker (הדרך הכי נפוצה כיום)

```bash
docker run -d \
  --name jenkins \
  -p 8080:8080 -p 50000:50000 \
  -v jenkins_home:/var/jenkins_home \
  jenkins/jenkins:lts-jdk17
```

טיפ חשוב: אם רוצים ש-Jenkins בתוך Docker יוכל להריץ containers נוספים (Docker-in-Docker), צריך להוסיף mount של ה-socket:

```bash
docker run -d \
  --name jenkins \
  -p 8080:8080 -p 50000:50000 \
  -v jenkins_home:/var/jenkins_home \
  -v /var/run/docker.sock:/var/run/docker.sock \
  jenkins/jenkins:lts-jdk17
```

## התקנה עם Docker Compose

```yaml
version: "3.8"
services:
  jenkins:
    image: jenkins/jenkins:lts-jdk17
    container_name: jenkins
    restart: unless-stopped
    ports:
      - "8080:8080"
      - "50000:50000"
    volumes:
      - jenkins_home:/var/jenkins_home
      - /var/run/docker.sock:/var/run/docker.sock
volumes:
  jenkins_home:
```

## שלב ה-Post-Installation Wizard

1. פתחו דפדפן בכתובת `http://localhost:8080`
2. Jenkins יבקש סיסמה ראשונית - מיקום הקובץ:
   ```bash
   sudo cat /var/lib/jenkins/secrets/initialAdminPassword
   ```
   ב-Docker:
   ```bash
   docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword
   ```
3. בוחרים "Install suggested plugins" (מומלץ למתחילים)
4. יוצרים משתמש admin ראשון
5. מגדירים את ה-Jenkins URL

## קבצי תצורה חשובים

- `JENKINS_HOME` - כל הנתונים, jobs, plugins, config
- `/etc/default/jenkins` (Linux) - הגדרות סביבה כמו פורט וזיכרון
- שינוי פורט ברירת מחדל:
  ```bash
  sudo nano /etc/default/jenkins
  # שנו: HTTP_PORT=8081
  sudo systemctl restart jenkins
  ```

## פתרון בעיות נפוצות

| בעיה | פתרון |
|---|---|
| Jenkins לא עולה אחרי restart | בדקו לוגים: `sudo journalctl -u jenkins -f` |
| "Port 8080 already in use" | שנו פורט או `sudo lsof -i :8080` כדי לזהות תהליך תופס |
| בעיית הרשאות על JENKINS_HOME | `sudo chown -R jenkins:jenkins /var/lib/jenkins` |
| Java version mismatch | ודאו JAVA_HOME מצביע לגרסה נתמכת |

## טיפים וטריקים
- תמיד גבו את `JENKINS_HOME` - זה מכיל את כל ה-jobs, credentials מוצפנים, ותצורה.
- אל תריצו Jenkins כ-root - זה נגד best practice אבטחתי.
- השתמשו ב-`jenkins.install.InstallState` system property אם רוצים לדלג על ה-wizard באוטומציה (למשל בסביבות Docker/CI).
- לסביבות production, שקלו reverse proxy (Nginx/Apache) עם HTTPS מול Jenkins.

## שאלות ראיון עבודה בנושא התקנה והגדרה

**ש: מה זה JENKINS_HOME ומה חשוב לדעת עליו?**
ת: תיקייה שמכילה את כל הנתונים של Jenkins - jobs, builds, plugins, config.xml, credentials מוצפנים. חובה לגבות אותה, ומעבר בין שרתים נעשה פשוט על ידי העתקת התיקייה.

**ש: מה ההבדל בין הרצת Jenkins כ-WAR standalone לבין Docker?**
ת: WAR מריץ ישירות עם Java על המכונה, פשוט לניהול ידני. Docker מספק בידוד, ניידות, וקל יותר לשכפול/scaling, אבל דורש טיפול מיוחד ב-persistent volumes ו-Docker-in-Docker אם צריך להריץ builds שמשתמשים ב-Docker.

**ש: איך הייתם ניגשים לשדרוג גרסת Jenkins בסביבת production?**
ת: קודם גיבוי מלא של JENKINS_HOME, בדיקה ב-staging, קריאת release notes לתאימות plugins, ואז שדרוג עם אפשרות rollback (snapshot/backup).

**ש: מה קורה אם שוכחים את סיסמת ה-admin?**
ת: אפשר לערוך את `config.xml` בתוך JENKINS_HOME כדי לבטל זמנית אימות (`useSecurity` ל-false), להיכנס מחדש וליצור משתמש/סיסמה חדשים, ואז להחזיר את ההגדרה.

**ש: מה ההבדל בין LTS ל-Weekly release של Jenkins?**
ת: LTS (Long Term Support) - גרסה יציבה יותר שעוברת בדיקות נוספות, מתעדכנת כל כ-12 שבועות, מומלצת ל-production. Weekly - עדכונים שוטפים עם פיצ'רים חדשים, פחות יציב.
