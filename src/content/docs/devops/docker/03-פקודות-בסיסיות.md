## ניהול Images

```bash
# הורדת image מ-Docker Hub
docker pull nginx
docker pull nginx:1.25          # גרסה (tag) ספציפית

# רשימת images מקומיים
docker images
docker image ls

# מחיקת image
docker rmi nginx
docker image rm nginx:1.25

# מחיקת כל ה-images שלא בשימוש (dangling)
docker image prune

# מחיקת כל ה-images שלא בשימוש על ידי אף container
docker image prune -a

# חיפוש image ב-Docker Hub מה-CLI
docker search nginx

# היסטוריית השכבות (layers) של image
docker history nginx
```

## ניהול Containers

### הרצה

```bash
# הרצה בסיסית (foreground - חוסם את הטרמינל)
docker run nginx

# הרצה ברקע (detached)
docker run -d nginx

# הרצה עם שם מותאם אישית
docker run -d --name web-server nginx

# מיפוי פורטים (host:container)
docker run -d -p 8080:80 nginx

# מיפוי כל הפורטים החשופים באופן אוטומטי
docker run -d -P nginx

# הרצה עם משתני סביבה
docker run -d -e "APP_ENV=production" -e "DEBUG=false" myapp

# הרצה עם מגבלות משאבים
docker run -d --memory="512m" --cpus="1.5" nginx

# הרצה אינטראקטיבית עם טרמינל (למשל לבדיקה בתוך קונטיינר)
docker run -it ubuntu bash

# מחיקה אוטומטית של הקונטיינר בסיום הריצה (מצוין לבדיקות זמניות)
docker run --rm -it alpine sh

# הרצה מחדש אוטומטית אם הקונטיינר נופל
docker run -d --restart unless-stopped nginx
```

אפשרויות ל-`--restart`:
- `no` - ברירת מחדל, לא מפעיל מחדש
- `on-failure[:max-retries]` - רק אם יצא עם קוד שגיאה
- `always` - תמיד, גם אחרי restart של Docker daemon
- `unless-stopped` - כמו always, אבל לא אם עצרתם אותו ידנית

### צפייה וניהול

```bash
# קונטיינרים פעילים
docker ps

# כל הקונטיינרים (כולל שנעצרו)
docker ps -a

# עצירה חינה (graceful - שולח SIGTERM ואז SIGKILL)
docker stop web-server

# עצירה מיידית (SIGKILL)
docker kill web-server

# הפעלה מחדש של קונטיינר שנעצר
docker start web-server

# restart (עצירה + הפעלה)
docker restart web-server

# מחיקת קונטיינר (חייב להיות עצור)
docker rm web-server

# עצירה ומחיקה בפעולה אחת
docker rm -f web-server

# מחיקת כל הקונטיינרים העצורים
docker container prune
```

### בדיקה ודיבוג

```bash
# לוגים
docker logs web-server
docker logs -f web-server        # follow - כמו tail -f
docker logs --tail 100 web-server
docker logs --since 10m web-server

# כניסה לקונטיינר רץ עם shell
docker exec -it web-server bash
docker exec -it web-server sh    # אם אין bash (למשל alpine)

# הרצת פקודה בודדת בתוך קונטיינר רץ
docker exec web-server ls /app

# מידע מפורט על קונטיינר (JSON מלא)
docker inspect web-server

# שימוש במשאבים (CPU, זיכרון, רשת) בזמן אמת - כמו top
docker stats
docker stats web-server

# תהליכים רצים בתוך קונטיינר
docker top web-server

# העתקת קבצים בין המארח לקונטיינר
docker cp web-server:/app/config.json ./config.json
docker cp ./local-file.txt web-server:/app/local-file.txt
```

## תגיות (Tags) וגרסאות Images

```bash
# תיוג image קיים בשם/גרסה חדשים
docker tag nginx myrepo/nginx:v1.0

# דחיפה ל-registry (אחרי docker login)
docker push myrepo/nginx:v1.0
```

**חשוב:** אם לא מציינים tag, Docker משתמש ב-`latest` כברירת מחדל. **טיפ קריטי לפרודקשן:** אל תסתמכו על `latest` - הוא לא בהכרח היציב ביותר, והוא עלול להשתנות מתחתיכם. השתמשו תמיד בגרסה ספציפית (`nginx:1.25.3`).

## ניקוי כללי (System Cleanup)

```bash
# מידע על שימוש בדיסק
docker system df

# ניקוי כולל - קונטיינרים עצורים, networks לא בשימוש, dangling images, build cache
docker system prune

# ניקוי אגרסיבי כולל volumes וכל ה-images שלא בשימוש
docker system prune -a --volumes
```

⚠️ **זהירות:** `docker system prune -a --volumes` מוחק גם volumes - אם יש שם נתונים חשובים (כמו דאטהבייס), הם יימחקו לצמיתות. תמיד בדקו קודם עם `docker volume ls`.

## דוגמה מלאה: מחזור חיים שלם

```bash
# 1. הורדת image
docker pull redis:7-alpine

# 2. הרצה עם שם, פורט, ו-restart policy
docker run -d --name my-redis -p 6379:6379 --restart unless-stopped redis:7-alpine

# 3. בדיקה שהוא רץ
docker ps

# 4. כניסה ובדיקה
docker exec -it my-redis redis-cli ping
# תשובה צפויה: PONG

# 5. צפייה בלוגים
docker logs my-redis

# 6. עצירה ומחיקה כשמסיימים
docker stop my-redis
docker rm my-redis
```

## טיפים וטריקים

- `docker ps -a -q` מחזיר רק את ה-IDs - שימושי לשילוב עם פקודות אחרות: `docker rm $(docker ps -a -q)` מוחק את כל הקונטיינרים.
- `--rm` הוא חבר טוב לבדיקות זמניות - חוסך צורך לזכור למחוק קונטיינרים.
- כדי לראות כמה מקום Docker תופס: `docker system df -v` נותן פירוט מלא לפי images/containers/volumes.
- שימוש ב-`docker exec` עדיף בהרבה על `docker attach` - attach מתחבר ל-process הראשי וקל "לתקוע" את הקונטיינר בטעות (Ctrl+C יעצור אותו).
- אפשר לקצר container ID - מספיק 3-4 תווים ראשונים כל עוד הם ייחודיים.

## שאלות ראיון נפוצות בנושא

1. **מה ההבדל בין `docker stop` ל-`docker kill`?**
   `stop` שולח SIGTERM (מבקש מהתהליך לסגור בעדינות), ומחכה (ברירת מחדל 10 שניות) לפני שהוא שולח SIGKILL בכוח. `kill` שולח SIGKILL מיידית.

2. **מה ההבדל בין `docker exec` ל-`docker attach`?**
   `exec` מריץ תהליך חדש בתוך הקונטיינר הרץ (לא משפיע על התהליך הראשי); `attach` מתחבר ל-stdin/stdout/stderr של התהליך הראשי (PID 1) עצמו.

3. **מה קורה אם לא מציינים tag בשם ה-image?**
   Docker מניח `latest` כברירת מחדל.

4. **איך מנקים דיסק שהתמלא מ-Docker?**
   `docker system prune -a --volumes` (בזהירות!), או בצורה ממוקדת יותר עם `docker image/container/volume prune`.

5. **מה עושה `--rm`?**
   מוחק אוטומטית את הקונטיינר ברגע שהוא מסיים לרוץ (יציאה או עצירה).
