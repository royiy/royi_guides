## אפשרויות התקנה

### 1. Docker Desktop (Windows / Mac) - מומלץ למתחילים

Docker Desktop הוא אפליקציה גרפית שכוללת:
- Docker Engine
- Docker CLI
- Docker Compose
- ממשק גרפי לניהול קונטיינרים, images ו-volumes
- ב-Windows: אינטגרציה עם WSL2 (Windows Subsystem for Linux)

**הורדה:** [Docker Desktop - דף הורדה רשמי](https://www.docker.com/products/docker-desktop/)

#### התקנה ב-Windows:

1. ודאו ש-WSL2 מותקן: פתחו PowerShell כמנהל והריצו:
```powershell
wsl --install
```
2. הורידו והריצו את מתקין Docker Desktop.
3. ודאו שבמהלך ההתקנה מסומן "Use WSL 2 instead of Hyper-V" (ברירת מחדל).
4. הפעילו מחדש את המחשב אם נדרש.
5. פתחו את Docker Desktop וודאו שהוא רץ (אייקון הלוויתן בשורת המשימות).

בדיקה שההתקנה הצליחה:
```bash
docker --version
docker run hello-world
```

### 2. התקנה על Linux (Ubuntu/Debian) - שיטת ה-Repository הרשמי

```bash
# הסרת גרסאות ישנות אם קיימות
sudo apt-get remove docker docker-engine docker.io containerd runc

# עדכון והתקנת תלויות
sudo apt-get update
sudo apt-get install ca-certificates curl gnupg

# הוספת מפתח ה-GPG הרשמי של Docker
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# הוספת ה-repository
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# התקנה
sudo apt-get update
sudo apt-get install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

בדיקה:
```bash
sudo docker run hello-world
```

### 3. Rootless mode ו-Docker ללא sudo

בברירת מחדל ב-Linux, כדי להריץ פקודות Docker צריך `sudo` (כי ה-daemon רץ כ-root). כדי להריץ בלי sudo:

```bash
# יצירת קבוצת docker (אם לא קיימת)
sudo groupadd docker

# הוספת המשתמש הנוכחי לקבוצה
sudo usermod -aG docker $USER

# יישום השינוי (או צאו והתחברו מחדש)
newgrp docker
```

**חשוב לדעת:** הוספת משתמש לקבוצת `docker` שקולה בפועל להענקת הרשאות root - כי כל מי שנמצא בקבוצה יכול להריץ קונטיינרים עם גישה מלאה למערכת הקבצים של המארח. זו שאלת אבטחה שחוזרת הרבה בראיונות עבודה.

## בדיקת תקינות ההתקנה

```bash
# גרסת Docker
docker --version

# מידע כללי על המערכת
```

## הגדרות ראשוניות מומלצות

### שינוי מיקום אחסון ה-Images (Linux)

אם יש לכם דיסק ייעודי לדוקר, אפשר לשנות את התיקייה ב-`/etc/docker/daemon.json`:

```json
{
  "data-root": "/mnt/docker-data"
}
```

לאחר השינוי:
```bash
sudo systemctl restart docker
```

### הגבלת לוגים (מומלץ מאוד לפרודקשן)

בברירת מחדל, לוגים של קונטיינרים יכולים לגדול בלי הגבלה ולמלא את הדיסק. הוסיפו ל-`/etc/docker/daemon.json`:

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
```

### הגדרת DNS מותאם

```json
{
  "dns": ["8.8.8.8", "8.8.4.4"]
}
```

## מבנה קבצים חשוב לדעת

| נתיב (Linux) | תיאור |
|---|---|
| `/var/lib/docker` | מיקום ברירת מחדל של כל נתוני Docker (images, containers, volumes) |
| `/etc/docker/daemon.json` | קובץ הגדרות ה-daemon |
| `/var/run/docker.sock` | ה-Unix Socket שדרכו הלקוח מדבר עם ה-daemon |
| `~/.docker/config.json` | הגדרות משתמש, כולל credentials ל-registries |

## התחברות ל-Docker Hub

```bash
docker login
# יבקש username ו-password (או Access Token - מומלץ יותר מסיסמה)

docker logout
```

**המלצת אבטחה:** במקום סיסמה, השתמשו ב-Access Token שנוצר דרך [Docker Hub Security Settings](https://hub.docker.com/settings/security) - כך אפשר לבטל גישה ספציפית בלי לשנות את הסיסמה הראשית.

## פתרון בעיות נפוצות

**"Cannot connect to the Docker daemon"**
- ודאו ש-Docker Desktop/השירות רץ: `sudo systemctl status docker`
- הפעילו את השירות: `sudo systemctl start docker`

**"permission denied while trying to connect to the Docker daemon socket"**
- זה קורה כשהמשתמש לא נמצא בקבוצת docker - ראו הוראות rootless למעלה.

**Docker Desktop איטי ב-Windows**
- ודאו שאתם עובדים בתוך קבצי המערכת של WSL2 (`\\wsl$\`) ולא ב-`C:\Users\...` - עבודה חוצה מערכות קבצים (Windows↔WSL2) איטית משמעותית.

## טיפים וטריקים

- ב-Windows, תמיד עדיפה עבודה עם WSL2 backend ולא Hyper-V - ביצועים טובים יותר ותאימות מלאה יותר.
- אחרי כל שינוי ב-`daemon.json`, תמיד `sudo systemctl restart docker`.
- שמרו גיבוי ל-`daemon.json` לפני עריכה - קובץ JSON לא תקין ימנע מהשירות לעלות כלל.
- בדקו תקינות JSON לפני restart: `python3 -m json.tool /etc/docker/daemon.json`

## שאלות ראיון נפוצות בנושא

1. **למה בברירת מחדל צריך sudo כדי להריץ פקודות Docker בלינוקס?**
   כי ה-Docker daemon רץ כ-root ומדבר עם הלקוח דרך Unix socket שבבעלות root; רק root או חברי קבוצת docker יכולים לגשת אליו.

2. **מה ההבדל בין Docker Engine ל-Docker Desktop?**
   Docker Engine הוא הליבה (daemon + CLI) שרצה על Linux; Docker Desktop הוא מוצר שלם ל-Windows/Mac שעוטף את ה-Engine (שרץ בתוך VM קליל) בממשק גרפי ובכלים נוספים.

3. **מה הסיכון בהוספת משתמש לקבוצת docker?**
   זה שווה ערך להענקת הרשאות root, כי אפשר להריץ קונטיינר עם `-v /:/host` ולקבל גישה מלאה למערכת הקבצים של המארח.

4. **איפה Docker שומר את הנתונים שלו כברירת מחדל בלינוקס?**
   ב-`/var/lib/docker`.
