# שאלות ראיון עבודה, טיפים וטריקים מרוכזים

מדריך זה מרכז את השאלות החשובות ביותר מכל המדריכים הקודמים, בתוספת שאלות מתקדמות נוספות, מסודרות לפי רמת קושי.

## שאלות ברמת Junior

**1. מה זה Docker ולמה משתמשים בו?**
פלטפורמה לקונטיינריזציה - אריזת אפליקציה עם כל התלויות שלה ליחידה עצמאית, נייעדת ועקבית שרצה זהה בכל סביבה.

**2. מה ההבדל בין Image ל-Container?**
Image = תבנית קריאה בלבד (blueprint). Container = מופע רץ של Image, עם שכבת כתיבה משלו (writable layer).

**3. מה ההבדל בין Container ל-Virtual Machine?**
VM מוירטואליזציה ברמת חומרה עם OS מלא לכל VM; Container חולק Kernel עם המארח ומבודד ברמת התהליך - קליל ומהיר בהרבה.

**4. מה זה Dockerfile?**
קובץ טקסט עם רשימת הוראות איך לבנות Docker Image.

**5. מה ההבדל בין CMD ל-ENTRYPOINT?**
CMD ניתן לדריסה מלאה בזמן הרצה. ENTRYPOINT קבוע (ברירת מחדל), ו-CMD יכול לשמש כפרמטרים ברירת מחדל לו.

**6. מה עושה `docker ps`? ומה ההבדל מ-`docker ps -a`?**
`docker ps` מציג קונטיינרים **פעילים** בלבד. `-a` מציג את **כל** הקונטיינרים כולל שנעצרו.

**7. מה זה Docker Hub?**
Registry ציבורי לאחסון ושיתוף Docker Images.

**8. איך רואים לוגים של קונטיינר?**
`docker logs <container>`, ועם `-f` לצפייה חיה (follow).

## שאלות ברמת Mid-Level

**9. מה זה Multi-stage Build ולמה זה חשוב?**
טכניקת Dockerfile עם כמה שלבי FROM, שרק התוצר האחרון מהם נכנס ל-image הסופי - מקטין דרסטית את הגודל ומסיר כלי build מיותרים מה-image הסופי.

**10. איך Layer Caching עובד ב-Docker, ולמה סדר ההוראות ב-Dockerfile חשוב?**
כל הוראה יוצרת שכבה; Docker בודק אם השכבה השתנתה (checksum) ומשתמש ב-cache אם לא. לכן כדאי לשים דברים "יציבים" (כמו התקנת תלויות) לפני דברים "משתנים" (כמו קוד האפליקציה).

**11. מה ההבדל בין Volume, Bind Mount ו-tmpfs?**
Volume - מנוהל ע"י Docker, מומלץ לפרודקשן. Bind Mount - נתיב ספציפי במארח, טוב לפיתוח. tmpfs - בזיכרון בלבד, נעלם עם עצירת הקונטיינר.

**12. מה ההבדל בין default bridge network ל-user-defined bridge?**
ב-user-defined יש DNS resolution אוטומטי לפי שם קונטיינר; ב-default צריך `--link` מיושן.

**13. למה מריצים קונטיינרים כמשתמש לא-root?**
כדי לצמצם נזק פוטנציאלי אם יש "בריחה" מהקונטיינר (container escape) - אם התהליך רץ כ-root, תוקף שבורח מקבל הרשאות root ישירות על המארח.

**14. מה ההבדל בין `docker stop` ל-`docker kill`?**
`stop` שולח SIGTERM (בקשה עדינה), מחכה, ואז SIGKILL. `kill` שולח SIGKILL מיידית וברוטלית.

**15. איך מנקים תמונות/קונטיינרים ישנים ומפנים מקום בדיסק?**
`docker system prune -a --volumes` (בזהירות, מוחק גם volumes), או פקודות ממוקדות: `docker image/container/volume prune`.

**16. מה עושה `depends_on` ב-Docker Compose, ומה המגבלה שלו?**
קובע סדר עלייה בין שירותים, אבל כברירת מחדל רק מוודא שהקונטיינר "התחיל", לא שהשירות "מוכן". הפתרון: שילוב עם `healthcheck` ו-`condition: service_healthy`.

## שאלות ברמת Senior / Advanced

**17. איך פועל User Namespace Remapping, ולמה זה חשוב לאבטחה?**
ממפה UIDs בתוך הקונטיינר (כולל root=0) ל-UIDs לא-פריווילגיים במארח, כך שגם "root" בתוך הקונטיינר לא באמת root במארח - שכבת הגנה נוספת מעבר להרצה כמשתמש לא-root.

**18. מה הסיכון בחשיפת `/var/run/docker.sock` לקונטיינר?**
זה שקול למתן הרשאות root מלאות על המארח - כי מי שיש לו גישה ל-socket יכול ליצור קונטיינרים חדשים עם כל הרשאה שרוצה, כולל mount של כל מערכת הקבצים של המארח.

**19. מה ההבדל בין Docker Swarm ל-Kubernetes, ומתי לבחור בכל אחד?**
Swarm - מובנה, פשוט יותר, טוב ל-clusters קטנים-בינוניים. Kubernetes - מורכב יותר להקמה, אך עוצמתי, גמיש, עם אקוסיסטם ותמיכה תעשייתית רחבה בהרבה - סטנדרט לרוב סביבות הפרודקשן הגדולות.

**20. איך Rolling Update עובד, ואיך מבצעים rollback אם יש בעיה?**
מעדכן instances אחד (או כמה) בכל פעם במקום את כולם יחד, כדי לשמור על זמינות. `docker service update --update-parallelism 1 --update-delay 30s` לשליטה בקצב, ו-`docker service rollback` לחזרה אחורה.

**21. איך Docker משתמש ב-namespaces וב-cgroups?**
Namespaces מבודדים "מה התהליך רואה" (mount, network, PID, user, IPC, UTS namespaces). cgroups מגבילים "כמה משאבים התהליך יכול לצרוך" (CPU, memory, I/O). ביחד הם יוצרים את הבידוד וההגבלה שמאפיינים קונטיינר.

**22. מה זה Linux Capabilities, ולמה עדיף `--cap-drop=ALL` + הוספה סלקטיבית?**
Capabilities מפרקים את הרשאות root ל"חתיכות" נפרדות (כמו קישור לפורט נמוך, יצירת raw socket). עקרון ההרשאה המינימלית אומר להסיר הכל ולהוסיף רק את מה שממש נדרש, כדי לצמצם משטח תקיפה.

**23. איך מטפלים בסודות (secrets) בצורה נכונה ב-Docker?**
לא ב-ENV/ARG קבועים ב-Dockerfile (נשארים בהיסטוריית ה-layers). במקום זאת: BuildKit secret mounts בזמן build, Docker Secrets ב-Swarm (מוצפן, מועבר דרך `/run/secrets`), או מנהלי סודות חיצוניים (Vault, AWS Secrets Manager).

**24. מה ההבדל בין Overlay network ל-Bridge network?**
Bridge - רשת מארח יחיד. Overlay - רשת מרובת-מארחים, מאפשרת לקונטיינרים על שרתים שונים לתקשר כאילו הם על אותה רשת - קריטי ל-Swarm/Kubernetes.

**25. איך אפשר לצמצם את גודל ה-Image הסופי?**
Multi-stage builds, image בסיס `-alpine`/`-slim`, ניקוי package cache באותה שכבה של ההתקנה, שילוב פקודות RUN, .dockerignore נכון, והימנעות מהתקנת תלויות פיתוח ב-image הסופי.

## תרחישי Troubleshooting נפוצים (שאלות מעשיות)

**"הקונטיינר שלי נופל מיד אחרי שהוא עולה"**
```bash
docker logs <container>          # לראות למה הוא נפל
docker inspect <container>       # לבדוק exit code
```
סיבות נפוצות: תהליך ראשי (PID 1) יוצא מיד, שגיאת קונפיגורציה, health check נכשל.

**"אני לא יכול לגשת לשירות דרך localhost"**
- ודאו שיש `-p host:container` תואם.
- אם על WSL2/Docker Desktop, לפעמים צריך `127.0.0.1` ולא `0.0.0.0`.
- בדקו firewall.

**"הקונטיינר תופס דיסק/זיכרון ללא הגבלה"**
- הגדירו `--memory`, `--cpus`
- הגדירו log rotation ב-`daemon.json`

**"שינויים בקוד לא מופיעים בקונטיינר"**
- בפיתוח - ודאו שיש bind mount, לא רק COPY (שדורש rebuild).
- בפרודקשן - זה בכוונה (immutable images) - צריך `docker build` מחדש ו-deploy.

**"permission denied בגישה לקבצים ב-volume"**
- בעיית UID mismatch בין המארח לקונטיינר - ראו פתרונות במדריך Volumes.

## Cheat Sheet - הפקודות החשובות ביותר

```bash
# מידע ובדיקה
docker --version
docker info
docker ps -a
docker images

# ניהול קונטיינרים
docker run -d --name X -p H:C image
docker exec -it X bash
docker logs -f X
docker stop X && docker rm X

# בנייה
docker build -t name:tag .
docker build --no-cache -t name:tag .

# ניקוי
docker system prune -a --volumes

# Compose
docker compose up -d
docker compose down
docker compose logs -f
docker compose exec service_name bash

# Swarm
docker swarm init
docker service create --name X --replicas 3 image
docker service update --image new-image X

# רשתות ואחסון
docker network create net-name
docker volume create vol-name
```

## המלצות ללימוד המשך

1. תרגלו בניית Dockerfile לפרויקט אמיתי משלכם (לא רק "hello world").
2. תרגלו הרמת סטאק שלם (frontend + backend + db) עם Docker Compose.
3. הקימו Swarm cluster מקומי עם כמה VMs (או Multipass/Vagrant) כדי להבין orchestration בפועל.
4. עברו למחקר על Kubernetes - הוא הצעד הטבעי הבא אחרי שליטה ב-Docker.
5. תרגלו סריקת אבטחה עם Trivy או Docker Scout על images שאתם בונים.
