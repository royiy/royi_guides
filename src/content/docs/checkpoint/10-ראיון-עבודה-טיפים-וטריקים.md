## איך בנוי ראיון עבודה טיפוסי ל-Check Point Engineer/Administrator

בדרך כלל ראיון כזה כולל 3 שכבות:

1. **שאלות תיאורטיות** - הבנת ארכיטקטורה, מושגי יסוד.
2. **שאלות תרחיש (Scenario-Based)** - "משתמש מתלונן ש-X, איך אתה ניגש לפתור?"
3. **שאלות פרקטיות/CLI** - הכרת פקודות, ולעיתים אפילו משימה חיה על מעבדה (Lab).

## שאלות ארכיטקטורה ויסודות

<details class="qa">
<summary>1. מהי ארכיטקטורת שלוש השכבות של Check Point ומה תפקיד כל רכיב?</summary>

Security Gateway אוכף את המדיניות על התעבורה, Security Management Server מחזיק את המדיניות, האובייקטים והלוגים, ו-SmartConsole הוא ממשק הניהול שמתחבר לשרת הניהול. ההפרדה מאפשרת ניהול ריכוזי של גייטוויים רבים, ואכיפה שממשיכה לעבוד גם אם הניהול אינו זמין.

</details>

<details class="qa">
<summary>2. מהו SIC ואיך הוא עובד?</summary>

Secure Internal Communication — ערוץ מאומת ומוצפן בין רכיבי Check Point, מבוסס תעודות שמנפיקה ה-Internal CA שעל שרת הניהול. מאתחלים אותו עם Activation Key משני הצדדים; הוא דורש שעון מסונכרן וקישוריות, ובלעדיו אין התקנת מדיניות ואין לוגים.

</details>

<details class="qa">
<summary>3. הסבירו את מושג ה-Stateful Inspection.</summary>

בדיקה שמנהלת טבלת חיבורים וזוכרת את ההקשר של כל session — מי יזם, באיזה שלב הוא נמצא ומה צפוי לחזור. כך תעבורת התשובה מותרת אוטומטית בלי כלל נפרד, וחבילה שאינה שייכת לחיבור קיים נחסמת, בניגוד ל-Packet Filtering חסר-זיכרון.

</details>

<details class="qa">
<summary>4. מה ההבדל בין Standalone ל-Distributed Deployment?</summary>

ב-Standalone הגייטוויי והניהול על אותו שרת — מתאים לסביבה קטנה או למעבדה. ב-Distributed הם מופרדים, וזו הפריסה המקובלת בייצור: ניהול של כמה גייטוויים, הפרדת עומסים, וגמישות בתחזוקה ובשדרוגים.

</details>

<details class="qa">
<summary>5. מהם Software Blades ותנו דוגמאות.</summary>

יכולות אבטחה מודולריות שניתן להפעיל ולרשות בנפרד על אותה פלטפורמה — למשל Firewall, IPS, Application Control & URL Filtering, Anti-Bot, Threat Emulation ו-Identity Awareness.

</details>

<details class="qa">
<summary>6. מה ההבדל בין Gaia Clish ל-Expert Mode?</summary>

Clish הוא ה-shell הניהולי של Gaia עם פקודות מובנות (`show`/`set`) ושמירה ב-`save config`. Expert Mode הוא bash מלא עם גישה למערכת הקבצים ולכלי אבחון כמו `fw`, `cphaprob` ו-`fw monitor`. נכנסים אליו בפקודה `expert`.

</details>

## שאלות מדיניות אבטחה ו-NAT

<details class="qa">
<summary>1. מה ההבדל בין Drop ל-Reject?</summary>

Drop משליך את החבילה בשקט והשולח מקבל timeout — מועדף כלפי רשתות לא אמינות כדי לא לחשוף מידע. Reject מחזיר RST או ICMP unreachable, כך שהיישום נכשל מיד — נוח יותר למשתמשים ברשת פנימית.

</details>

<details class="qa">
<summary>2. מהו Cleanup Rule ולמה הוא תמיד אחרון?</summary>

כלל Any/Any/Drop **עם לוג** בסוף ה-Rule Base. החסימה עצמה הייתה מתרחשת ממילא (Implicit Drop), אבל בלי הכלל הזה לא היה תיעוד — וחקירת תעבורה שנחסמה הופכת לבלתי אפשרית. הוא אחרון כי הבדיקה היא מלמעלה למטה.

</details>

<details class="qa">
<summary>3. הסבירו את ההבדל בין Hide NAT ל-Static NAT.</summary>

Hide NAT מסתיר רשת שלמה מאחורי כתובת אחת באמצעות פורטים (many-to-one) — לגלישה החוצה בלבד. Static NAT ממפה כתובת אחת לאחת בשני הכיוונים — לשרת פנימי שצריך להיות נגיש מבחוץ.

</details>

<details class="qa">
<summary>4. מה קורה אם כלל רחב יותר נמצא מעל כלל ספציפי ב-Rule Base?</summary>

הכלל הרחב "בולע" את הספציפי: הגייטוויי עוצר בהתאמה הראשונה, ולכן הכלל הספציפי לעולם לא ייאכף (Shadowed Rule). מזהים זאת ב-Hit Count אפסי ובכלי ניתוח ה-Rule Base, והפתרון הוא להעלות את הכלל הספציפי מעל הרחב.

</details>

<details class="qa">
<summary>5. מה זה Stealth Rule?</summary>

כלל מוקדם שחוסם כל תעבורה שמיועדת לגייטוויי עצמו (למעט ניהול מפורש שהותר לפניו), כדי להגן עליו מפני סריקות ותקיפות ישירות ו"להעלים" אותו מהרשת.

</details>

<details class="qa">
<summary>6. מהם Implied Rules?</summary>

כללים מובנים שנוצרים אוטומטית ומאפשרים את התקשורת החיונית של Check Point עצמה — SIC, לוגים ועדכונים. הם מוצגים רק כשמסמנים את התצוגה שלהם, וניתן לכבותם בסביבות מחמירות — בתנאי שכותבים במקומם כללים מפורשים.

</details>

## שאלות VPN

<details class="qa">
<summary>1. מה ההבדל בין Phase 1 ל-Phase 2 ב-IKE?</summary>

Phase 1 מקים ערוץ מאובטח בין העמיתים — אימות (PSK/תעודות) והחלפת מפתחות. Phase 2 מקים בתוכו את מנהרת ה-IPsec שבה עוברת התעבורה בפועל, ומסכים על הרשתות והאלגוריתמים. כשל באימות שייך ל-Phase 1, אי-התאמת רשתות ל-Phase 2.

</details>

<details class="qa">
<summary>2. מה זה VPN Domain?</summary>

הרשתות שנמצאות מאחורי כל עמית ואמורות לעבור במנהרה. אי-התאמה בהגדרה בין שני הצדדים היא סיבה נפוצה מאוד לכך שהמנהרה לא עולה או שרק חלק מהתעבורה עוברת.

</details>

<details class="qa">
<summary>3. הסבירו Meshed לעומת Star Community.</summary>

ב-Meshed כל אתר מחובר לכל אתר — תעבורה ישירה בין סניפים אך ריבוי מנהרות. ב-Star הסניפים (Satellites) מתחברים למרכז (Center) בלבד — ניהול פשוט ובקרה מרוכזת, במחיר תעבורה עקיפה בין סניפים.

</details>

<details class="qa">
<summary>4. מה ההבדל בין Domain-Based ל-Route-Based VPN?</summary>

ב-Domain-Based מה שנכנס למנהרה נקבע לפי רשימת הרשתות (VPN Domain). ב-Route-Based נוצר ממשק מנהרה (VTI) וההחלטה נעשית לפי טבלת הניתוב — מה שמאפשר ניתוב דינמי (OSPF/BGP) וטופולוגיות מורכבות, במיוחד מול ספקי ענן.

</details>

<details class="qa">
<summary>5. איך הייתם מתחילים לאבחן תקלת VPN?</summary>

לבדוק היכן זה נתקע: `vpn tu` למצב המנהרות, לוגי VPN ב-SmartLog, ואז — אם Phase 1 נכשל — אימות, NAT-T וקישוריות UDP/500 ו-4500; אם Phase 2 נכשל — התאמת encryption domain ואלגוריתמים. לצורך העמקה `vpn debug ikeon` וניתוח `ike.elg`.

</details>

## שאלות Identity Awareness

<details class="qa">
<summary>1. מה ההבדל בין AD Query ל-Identity Agent?</summary>

AD Query הוא clientless וקורא אירועי התחברות מבקרי הדומיין — קל לפריסה, פחות מדויק ומתעדכן באיחור. Identity Agent הוא סוכן בתחנה שמדווח בזמן אמת, תומך ב-SSO ומזהה החלפת משתמשים — מדויק יותר, אך דורש התקנה.

</details>

<details class="qa">
<summary>2. מהו Access Role?</summary>

אובייקט מבוסס זהות (משתמשים, קבוצות AD, מכונות, מיקום רשת) שמאפשר לכתוב כללים לפי "מי" ולא לפי כתובת IP — וכך הכלל ממשיך לעבוד גם כשהמשתמש מחליף עמדה או מקבל IP אחר.

</details>

<details class="qa">
<summary>3. איך פותרים מצב שבו AD Query לא מזהה משתמשים?</summary>

בודקים הרשאות של חשבון השירות לקריאת Security Log בבקרי הדומיין, פתיחת WMI/DCOM (פורט 135 ופורטים דינמיים) ו-LDAP, סנכרון שעון ו-DNS, ושאירועי 4624 נרשמים בפועל. לאבחון: `adlog a dc` ו-`pdp monitor all`.

</details>

## שאלות Threat Prevention

<details class="qa">
<summary>1. מה ההבדל בין IPS ל-Anti-Bot?</summary>

IPS מזהה ומונע ניסיונות ניצול פגיעויות בתעבורה — כלומר את ההדבקה. Anti-Bot מזהה מכונה שכבר נדבקה לפי תקשורת עם שרתי שליטה (C&C) ועוצר אותה.

</details>

<details class="qa">
<summary>2. הסבירו Threat Emulation מול Threat Extraction.</summary>

Threat Emulation מריץ את הקובץ ב-Sandbox כדי לזהות התנהגות זדונית — מדויק מול Zero-Day אך לוקח זמן. Threat Extraction מסיר רכיבים פעילים (מאקרו, סקריפטים) ומספק גרסה נקייה מיד. בפועל משלבים את שניהם.

</details>

<details class="qa">
<summary>3. מה זה ThreatCloud?</summary>

מאגר מודיעין האיומים הענני של Check Point, שמאגד נתונים מחיישנים ברחבי העולם ומפיץ אינדיקטורים וחתימות לכלל הגייטוויים תוך דקות — כך שאיום שהתגלה במקום אחד נחסם מיד אצל כולם.

</details>

## שאלות ניטור ולוגים

<details class="qa">
<summary>1. מה ההבדל בין SmartLog ל-SmartEvent?</summary>

SmartLog הוא חיפוש מהיר בלוגים הגולמיים לחקירה נקודתית. SmartEvent מבצע קורלציה בין אירועים, מזהה תקיפות ומגמות, ומספק dashboards, התרעות ודוחות.

</details>

<details class="qa">
<summary>2. מה מציגה <code>fw ctl pstat</code>?</summary>

סטטיסטיקות פנימיות של ה-kernel: זיכרון, מספר החיבורים בטבלה מול המקסימום, נתוני NAT וסנכרון קלאסטר. שימושי לזיהוי מיצוי משאבים שמתבטא בתקלות תעבורה "אקראיות".

</details>

<details class="qa">
<summary>3. איך הייתם מאתרים למה חבילה נחסמה?</summary>

סינון ב-SmartLog לפי מקור, יעד, שירות וזמן, ובדיקת ה-Action, ה-Blade והכלל בשורת הלוג. אם הלוג אינו מספיק — `fw monitor` כדי לראות באיזו נקודה (i/I/o/O) החבילה נעלמה.

</details>

## שאלות Clustering

<details class="qa">
<summary>1. מה ההבדל בין HA Mode ל-Load Sharing Mode?</summary>

ב-HA חבר אחד Active והשני Standby מסונכרן — פשוט וצפוי. ב-Load Sharing כל החברים מעבדים תעבורה בו-זמנית ומגדילים תפוקה, במחיר מורכבות באבחון ותלות בהתנהגות המתגים והפרוטוקולים.

</details>

<details class="qa">
<summary>2. מה תפקיד ה-Sync Interface?</summary>

להעביר בין חברי הקלאסטר את טבלת החיבורים ומידע המצב, כך שב-Failover החיבורים הקיימים שורדים. הוא חייב להיות ייעודי ומהיר — עיכוב או אובדן בו מובילים לסנכרון חלקי ואף ל-split-brain.

</details>

<details class="qa">
<summary>3. איך מבצעים תחזוקה על קלאסטר בלי השבתה?</summary>

עובדים חבר אחרי חבר: מורידים את ה-Standby (`clusterXL_admin down`), מעדכנים, מאמתים (`cphaprob stat`), מחזירים, מבצעים Failover מבוקר ורק אז מטפלים בחבר השני — הכול בחלון תחזוקה ותוך ווידוא תאימות גרסאות.

</details>

## שאלות Troubleshooting מתקדמות (לתפקידים בכירים)

<details class="qa">
<summary>1. הסבירו איך עובד <code>fw monitor</code> ומה ההבדל בין נקודות i/I/o/O.</summary>

הכלי לוכד חבילות בארבע נקודות בשרשרת העיבוד: i לפני בדיקת הכניסה, I אחריה, o לפני בדיקת היציאה ו-O אחריה. ההשוואה בין הנקודות מראה בדיוק היכן החבילה נעלמה — האם הגייטוויי חסם אותה, ובאיזה שלב.

</details>

<details class="qa">
<summary>2. מה זה CoreXL ואיך בודקים חלוקת עומס בין ליבות?</summary>

CoreXL מריץ כמה מופעי Firewall במקביל על ליבות שונות. בודקים עם `fw ctl affinity -l -a` את מיפוי הליבות והממשקים, ועם `cpview`/`top` האם ליבה בודדת רוויה בזמן שאחרות פנויות — מצב שנגרם לרוב מ-elephant flow או מ-affinity לא מתאים.

</details>

<details class="qa">
<summary>3. מה חשוב לאסוף לפני פתיחת קייס ל-TAC?</summary>

`cpinfo` מהגייטוויי ומהניהול, גרסה ו-Hotfixes, תיאור מדויק של התקלה ומתי התחילה, לוגים רלוונטיים, לכידות תעבורה (`fw monitor`/`tcpdump`) ותיאור השינויים האחרונים בסביבה.

</details>

<details class="qa">
<summary>4. תארו תקלה מורכבת שפתרתם (או הייתם פותרים) ואיך ניגשתם אליה.</summary>

זו שאלת התנהגות — בונים סיפור בשלושה חלקים: **מה קרה** (למשל "אחרי הוספת רשת חדשה, חלק מהתעבורה נחסמה לסירוגין"), **איך ניגשתי** (איסוף עובדות מהלוג, בידוד השכבה, `fw monitor` שהראה חסימת Anti-Spoofing בגלל topology לא מעודכן), ו**מה התוצאה והלקח** (עדכון ה-topology, התקנת מדיניות, והוספת בדיקה לנוהל שינויים). חשוב להראות שיטתיות ותיעוד, לא ניחושים.

</details>

## "שאלת מלכודת" קלאסית - תרגלו אותה!

**שאלה:** "יש לי כלל ב-Rule Base שאומר Accept מ-Any ל-Server X בפורט 443, אבל המשתמשים עדיין לא מצליחים לגשת. מה יכול להיות הבעיה?"

**תשובה טובה תכלול כמה כיוונים אפשריים**, לא רק אחד:
- ייתכן שיש כלל **מעל** אותו כלל שכבר תופס את התעבורה (Drop).
- בעיית **NAT** - אולי כתובת ה-Destination המקורית לא תואמת בגלל Static NAT שלא הוגדר נכון.
- בעיית **Routing** - התעבורה בכלל לא מגיעה לגייטווי.
- **Threat Prevention** עשוי לחסום למרות שה-Firewall Rule מאשר (Blade נפרד!).
- בעיה ברמת ה-Server עצמו (לא Check Point בכלל).

זו שאלה שבודקת אם אתם חושבים בצורה שיטתית (Layered Thinking) ולא קופצים למסקנות.

## טיפים כלליים להצלחה בראיון

- **דברו בקול רם את תהליך החשיבה** - מראיינים רוצים לראות איך אתם ניגשים לבעיה, לא רק את התשובה הסופית.
- **אל תפחדו להגיד "לא יודע, אבל הנה איך הייתי בודק"** - זה תמיד עדיף על ניחוש שגוי בביטחון.
- הכירו את ההבדל בין **Firewall Layer, Application Layer, ו-Threat Prevention Layer** - שאלה נפוצה שבודקת הבנה אדריכלית.
- אם מדובר בתפקיד עם דגש על Automation - הכירו בסיס על **Check Point API** (Management API - `mgmt_cli`) לניהול תצורה דרך סקריפטים.

```bash
# דוגמה לפקודת Management API בסיסית
mgmt_cli login -u admin -p <password> --format json
mgmt_cli show-hosts --format json
```

- הכינו **סיפור STAR** (Situation, Task, Action, Result) לפחות לתקלה מורכבת אחת שפתרתם - שאלות התנהגותיות ("ספר לי על תקלה שפתרת") נפוצות מאוד גם בתפקידים טכניים.

## רמות הסמכה (Certifications) שכדאי להכיר

| הסמכה | תיאור |
|---|---|
| **CCSA** | Security Administrator - רמת בסיס, ניהול יומיומי |
| **CCSE** | Security Expert - רמה מתקדמת, Troubleshooting, VPN, Cluster |
| **CCSM** | Security Master - רמת מומחה, אחרי CCSE + Specializations |
| **CCSM Elite** | הרמה הגבוהה ביותר |

מומלץ מאוד להזכיר בראיון אם יש לכם הסמכה פעילה, או תוכנית לרכוש אחת - זה מראה רצינות מקצועית.

## טיפים וטריקים כלליים לעבודה יומיומית (לא רק לראיון)

- תמיד לתעד שינויים במדיניות (Change Management) - Check Point תומך ב-**Session Management** שמאפשר לראות מי שינה מה ומתי.
- לפני שינוי גדול, השתמשו ב-**Publish/Discard** של Session במקום לעבוד ישירות על ה-Policy החי.
- גבו קונפיגורציה באופן קבוע (`migrate export` על ה-SMS).
- הכירו את ה-**Check Point CheckMates Community** - מקור עצום לפתרון בעיות אמיתיות מהשטח, כולל תשובות מעובדי Check Point עצמם.

```bash
# גיבוי מלא של ה-Management Database
migrate export -v R81.20 /var/log/backup_export.tgz
```
