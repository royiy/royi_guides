## תכנון לפני התקנה

לפני שמתחילים, יש לענות על מספר שאלות:

- **Standalone או Distributed?** מכונה אחת שמריצה גם SMS וגם Gateway, או שני שרתים נפרדים?
- **גודל הסביבה** - כמה Gateways ינוהלו? זה ישפיע על ה-Sizing (RAM, CPU, דיסק) של ה-SMS.
- **גרסה** - מומלץ להתקין את הגרסה היציבה העדכנית (למשל R81.20 עם JHF - Jumbo Hotfix - עדכני).

## שלב 1: התקנת Gaia OS

התקנת Gaia מתבצעת מ-ISO רשמי (מורד מ-UserCenter/Portal של Check Point). תהליך ההתקנה כולל:

1. בחירת שפה, Keyboard Layout ו-Time Zone.
2. הגדרת סיסמת Admin ראשונית.
3. הגדרת כתובת IP זמנית לממשק הניהול (Management Interface).
4. לאחר הריבוט הראשון - כניסה ל-WebUI בכתובת `https://<Management-IP>` להמשך ה-**First Time Configuration Wizard (FTW)**.

## שלב 2: אשף ה-First Time Wizard

ב-Wizard מגדירים:

- **Installation Type**: Security Gateway ו/או Security Management, Standalone.
- **Interfaces** - הגדרת IP, Subnet Mask, ו-Topology (Internal/External) לכל ממשק.
- **Hostname ו-DNS**
- **NTP** - קריטי! שעון לא מסונכרן גורם לבעיות SIC, לוגים ו-VPN.
- **הפעלת SIC** - הגדרת One-Time Password (Activation Key) שישמש לחיבור SmartConsole/SMS לגייטווי.

```bash
# בדיקת שעון וזמן ב-Gaia (Clish)
show clock
show ntp servers

# הגדרת NTP
set ntp active on
set ntp server primary <IP> version 4
```

## שלב 3: התקנת SmartConsole

SmartConsole הוא אפליקציית Windows (יש גם גרסה שרצה ב-Cloud/Container) שמתחברים דרכה ל-Management Server. יורדת מ-SmartConsole Download Page של Check Point. יש לוודא **התאמת גרסה** בין SmartConsole לגרסת ה-SMS - זו טעות נפוצה מאוד למתחילים.

בהתחברות ראשונה:

```
Server: <Management IP>
Username: admin
Password: <הסיסמה שהוגדרה ב-FTW>
```

## שלב 4: יצירת אובייקט Gateway ב-SmartConsole

לאחר החיבור, יוצרים אובייקט **Check Point Gateway** ב-SmartConsole:

1. `Gateways & Servers` -> `New` -> `Gateway`
2. מזינים שם, IP ניהול.
3. מגדירים **SIC** - מזינים את ה-Activation Key שהוגדר בגייטווי (`cpconfig` -> Secure Internal Communication).
4. לוחצים `Initialize` - אם התהליך מצליח, יופיע "Trust established".
5. מגדירים אילו Software Blades פעילים על הגייטווי הזה.
6. מגדירים **Topology** של הממשקים - איזה ממשק External ואיזה Internal (חיוני ל-Anti-Spoofing).

## הפעלת SIC דרך CLI בגייטווי (חלופה ל-WebUI)

```bash
cpconfig
# בחרו: Secure Internal Communication
# הזינו Activation Key (מינימום 4 תווים, מומלץ מורכב יותר)
```

## שלב 5: Policy Install ראשוני

לאחר בניית מדיניות בסיסית (Rule Base) - ראו מדריך 3 - יש להתקין אותה על הגייטווי:

`Install Policy` ב-SmartConsole -> בחירת הגייטווי -> `Install`.

ב-Backend מתבצעים שני שלבים: **Verify Policy** (בדיקת syntax ותקינות) ו-**Compile & Push** (המרה לקוד ודחיפה בפועל לגייטווי).

## Licensing (רישוי)

יש להטמיע רישיון (License) עבור כל Gateway ו-SMS. אפשר לנהל את זה דרך **User Center** (Cloud) או ידנית:

```bash
# הצגת רישיונות מותקנים
cplic print

# הוספת רישיון ידנית מקובץ
cplic put -o <license_file>
```

## דוגמה מלאה - Lab Standalone קטן

מכונה וירטואלית (VMware/VirtualBox) עם:
- `eth0` -> Management + External, IP: 10.0.0.10/24
- `eth1` -> Internal, IP: 192.168.1.1/24

לאחר FTW, מתחברים מ-SmartConsole מהמחשב האישי דרך `10.0.0.10`, בונים כלל בסיסי שמאפשר יציאה לאינטרנט מה-LAN, ומתקינים מדיניות.

## טיפים וטריקים

- **תמיד** לגבות (Snapshot) לפני שדרוגים או שינויים משמעותיים: `snapshot` בגישה מ-Gaia CLI, או Snapshot ב-Hypervisor.
- אם ה-SIC לא מתחבר - בדקו קודם כל **שעון** (NTP), אחר כך **Firewall בדרך** (חסימת פורט 18211), ולבסוף Activation Key שגוי/פג תוקף.
- מומלץ תמיד להתקין **Jumbo Hotfix Accumulator (JHF)** עדכני על גבי גרסת ה-Base - כמעט אף פעם לא רצים בייצור בלי JHF.
- שימוש בפקודת `cpinfo` ליצירת קובץ אבחון מקיף (שימושי גם לפני פנייה ל-TAC).

```bash
cpinfo -o output.tgz
```
