שאלות חזרה אינטראקטיביות על כל מה שלמדתם לאורך סדרת מדריכי ה-Terraform (יסודות ו-Workflow, שפת HCL, Providers/Resources/Data Sources, ניהול State, Modules, Workspaces, Best Practices ואבטחה, CI/CD, וסיכום שאלות הראיון). בחרו תשובה בכל שאלה ותקבלו מיד משוב האם היא נכונה, יחד עם הסבר.

<div id="quiz-score" class="quiz-score">ענית נכון על 0 מתוך 10</div>

<div class="quiz-card" data-answer="א">
  <p class="quiz-question"><strong>1. מדוע תכונת ה-Idempotency קריטית ל-Terraform?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. כי היא מבטיחה שהרצה חוזרת של <code>terraform apply</code> על אותו קוד, כשדבר לא השתנה בפועל, לא תשנה כלום - זה הבסיס לכך שאפשר להריץ את אותו קוד שוב ושוב בבטחה</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. כי היא מונעת מ-Terraform להוריד providers מחדש</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. כי היא הופכת את הקוד מ-declarative ל-imperative</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. כי היא מייתרת לגמרי את הצורך בקובץ state</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> Idempotency אומרת שהרצה חוזרת של <code>terraform apply</code> על אותו קוד לא אמורה לשנות דבר אם כלום לא השתנה בפועל. זו תכונת יסוד שמבטיחה עקביות ומאפשרת להריץ את אותו קוד פעמים רבות בבטחה, בלי תוצאות לוואי לא צפויות.</div>
</div>

<div class="quiz-card" data-answer="ג">
  <p class="quiz-question"><strong>2. למה נחשב שימוש ב-<code>terraform plan -target</code> לאנטי-פטרן בסביבת פרודקשן?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. כי הדגל <code>-target</code> לא נתמך החל מגרסה 1.0 ואילך</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. כי הוא מוחק אוטומטית את כל קובץ ה-state</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. כי הוא מתעלם מגרף התלויות המלא (DAG) ועלול להשאיר את ה-state לא מסונכרן עם שאר המשאבים - שימושי רק לדיבוג נקודתי, ותמיד יש להריץ אחריו <code>plan</code> מלא</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. כי הוא דורש הרשאות אדמין ייעודיות בענן</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> <code>-target</code> שימושי לדיבוג נקודתי אבל מסוכן בפרודקשן, כי הוא מתמקד במשאב בודד ומתעלם משאר גרף התלויות - מה שעלול להשאיר את ה-state במצב לא עקבי. הכלל הוא להשתמש בו רק לצורך דיבוג, ותמיד להריץ אחריו <code>plan</code> מלא כדי לוודא שהכל תקין.</div>
</div>

<div class="quiz-card" data-answer="ד">
  <p class="quiz-question"><strong>3. מה הסיכון המרכזי בשימוש ב-<code>count</code> כשמסירים פריט מאמצע רשימה, לעומת <code>for_each</code>?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. <code>count</code> ו-<code>for_each</code> זהים לחלוטין בהתנהגותם בכל תרחיש</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. <code>count</code> עובד רק עם <code>map</code>, ו-<code>for_each</code> עובד רק עם <code>list</code></button>
    <button class="quiz-option" type="button" data-choice="ג">ג. אין שום סיכון בפועל, זו רק שאלת סגנון כתיבת קוד</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. Terraform "מזיז" את כל האינדקסים שאחרי הפריט שהוסר ועלול להרוס וליצור מחדש משאבים שלא היו אמורים להשתנות; <code>for_each</code> עם מפתחות ייחודיים פותר זאת כי כל עותק מזוהה לפי מפתח קבוע ולא לפי מיקום</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> <code>count</code> מבוסס על אינדקס מספרי - הסרת פריט מהאמצע "מזיזה" את כל האינדקסים שאחריו, מה שגורם ל-Terraform להציע destroy/recreate על משאבים שלא היו אמורים להשתנות כלל. <code>for_each</code> עם מפתחות ייחודיים (set/map) יציב יותר כי כל עותק מזוהה לפי מפתח קבוע.</div>
</div>

<div class="quiz-card" data-answer="א">
  <p class="quiz-question"><strong>4. מה עושה <code>lifecycle { create_before_destroy = true }</code> ולמה זה חשוב?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. גורם ל-Terraform ליצור את המשאב החדש לפני מחיקת הישן, במקום ברירת המחדל (מחיקה ואז יצירה) - קריטי למניעת downtime במשאבים כמו launch templates וקונפיגורציות load balancer</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. מוחק את המשאב הישן מיד, ורק לאחר מכן יוצר את החדש</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. מונע כל שינוי עתידי במשאב לצמיתות</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. מסמן את המשאב כ-<code>sensitive</code> בפלטי plan/apply</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> ברירת המחדל של Terraform היא מחיקה ואז יצירה מחדש (destroy-then-create). <code>create_before_destroy</code> הופך את הסדר - יוצר קודם את המשאב החדש - וכך מונע חלון זמן ללא שירות (downtime), חשוב במיוחד למשאבים כמו launch templates ו-AMIs.</div>
</div>

<div class="quiz-card" data-answer="ג">
  <p class="quiz-question"><strong>5. אם מסמנים משתנה או output כ-<code>sensitive = true</code>, האם הסוד מוגן גם בקובץ ה-state עצמו?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. כן, <code>sensitive</code> מצפין אוטומטית את הערך גם בקובץ ה-state</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. כן, אבל רק אם ה-backend המשמש הוא S3</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. לא - <code>sensitive</code> רק מסתיר את הערך מפלטי <code>plan</code>/<code>apply</code>/<code>output</code> הרגילים; קובץ ה-state עדיין שומר אותו בטקסט גלוי, ולכן יש להגן על ה-state עצמו (הצפנה, הרשאות גישה מדויקות)</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. <code>sensitive</code> מוחק את הערך לגמרי מקובץ ה-state</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> קובץ ה-state שומר את כל ה-attributes של המשאבים, כולל סודות, בטקסט גלוי - גם אם סומנו <code>sensitive</code> בקוד. הדגל הזה רק מסתיר את הערך מהפלט הרגיל. ההגנה האמיתית היא הצפנת ה-state (encryption at rest) והגבלת גישה ל-backend לפי עקרון least privilege.</div>
</div>

<div class="quiz-card" data-answer="ד">
  <p class="quiz-question"><strong>6. למה מומלץ שלא לכלול בלוק <code>provider</code> בתוך מודול משותף (shared module)?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. כי HCL לא תומך טכנית בבלוק <code>provider</code> בתוך module</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. כי זה מונע שימוש ב-<code>for_each</code> על בלוק ה-<code>module</code></button>
    <button class="quiz-option" type="button" data-choice="ג">ג. כי זה גורם ל-<code>terraform init</code> להיכשל תמיד</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. כי זה "נועל" את המודול לקונפיגורציית provider ספציפית (region, credentials) ומונע גמישות מהצוותים שמשתמשים בו; עדיף להעביר providers מבחוץ עם ה-meta-argument <code>providers</code></button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> מודול משותף אמור להיות גמיש לכל קונפיגורציה שקוראת לו. אם הוא מגדיר בעצמו בלוק <code>provider</code>, הוא "נועל" את הקורא לאותו region/credentials. הדרך הנכונה היא שהמודול יקבל providers מבחוץ באמצעות ה-meta-argument <code>providers</code>.</div>
</div>

<div class="quiz-card" data-answer="ב">
  <p class="quiz-question"><strong>7. מה ממליצה HashiCorp באופן רשמי לגבי שימוש ב-CLI Workspaces להפרדת סביבות prod/staging/dev?</strong></p>
  <div class="quiz-options">

    function updateScore() {
      if (!scoreEl) return;
      var correctCount = document.querySelectorAll('.quiz-card--answered[data-was-correct="true"]').length;
      scoreEl.textContent = 'ענית נכון על ' + correctCount + ' מתוך ' + cards.length;
    }

    function answerCard(card, chosenBtn) {
      var correct = card.getAttribute('data-answer');
      var chosen = chosenBtn.getAttribute('data-choice');
      var isCorrect = chosen === correct;

      card.classList.add('quiz-card--answered');
      card.setAttribute('data-was-correct', isCorrect ? 'true' : 'false');

      var options = card.querySelectorAll('.quiz-option');
      options.forEach(function (opt) {
        opt.disabled = true;
        if (opt.getAttribute('data-choice') === correct) {
          opt.classList.add('quiz-option--correct');
        } else if (opt === chosenBtn) {
          opt.classList.add('quiz-option--incorrect');
        }
      });

      var result = card.querySelector('.quiz-result');
      if (result) {
        result.textContent = isCorrect ? '✅ נכון!' : '❌ לא נכון - התשובה הנכונה מסומנת בירוק.';
        result.classList.remove('quiz-result--correct', 'quiz-result--incorrect');
        result.classList.add(isCorrect ? 'quiz-result--correct' : 'quiz-result--incorrect');
      }

      updateScore();
    }

    function resetCard(card) {
      card.classList.remove('quiz-card--answered');
      card.removeAttribute('data-was-correct');
      var options = card.querySelectorAll('.quiz-option');
      options.forEach(function (opt) {
        opt.disabled = false;
        opt.classList.remove('quiz-option--correct', 'quiz-option--incorrect');
      });
      var result = card.querySelector('.quiz-result');
      if (result) {
        result.textContent = '';
        result.classList.remove('quiz-result--correct', 'quiz-result--incorrect');
      }
    }

    cards.forEach(function (card) {
      card.querySelectorAll('.quiz-option').forEach(function (btn) {
        btn.addEventListener('click', function () {
          if (card.classList.contains('quiz-card--answered')) return;
          answerCard(card, btn);
        });
      });
    });

    if (resetAllBtn) {
      resetAllBtn.addEventListener('click', function () {
        cards.forEach(resetCard);
        updateScore();
      });
    }

    updateScore();
  }

  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', initQuiz);
  } else {
    initQuiz();
  }
})();
</script>
