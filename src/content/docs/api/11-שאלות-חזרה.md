שאלות חזרה אינטראקטיביות על כל מה שלמדתם לאורך מדריכי ה-API (מבוא ל-API ו-REST, HTTP Methods ו-Status Codes, אימות והרשאה, עקרונות לתכנון API, Versioning, GraphQL, אבטחת API, תיעוד עם OpenAPI/Swagger, בדיקות/Caching/Rate Limiting, ושאלות ראיון עבודה מקיפות). בחרו תשובה בכל שאלה ותקבלו מיד משוב האם היא נכונה, יחד עם הסבר.

<div class="quiz-card" data-answer="א">
  <p class="quiz-question"><strong>1. מי הגדיר את סגנון הארכיטקטורה REST, ובאיזה הקשר?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. רוי פילדינג (Roy Fielding), בעבודת הדוקטורט שלו משנת 2000</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. טים ברנרס-לי (Tim Berners-Lee), כחלק מהגדרת HTML</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. צוות Google, כחלק מפיתוח gRPC</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. ארגון ה-OWASP, כחלק מתקן אבטחה</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> REST (Representational State Transfer) הוא סגנון ארכיטקטוני, לא פרוטוקול או תקן פורמלי, שהוגדר על ידי רוי פילדינג בעבודת הדוקטורט שלו ב-2000. API שעומד בעקרונות שלו נקרא "RESTful".</div>
</div>

<div class="quiz-card" data-answer="ג">
  <p class="quiz-question"><strong>2. מה ההבדל בין קודי הסטטוס <code>401</code> ל-<code>403</code>?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. אין הבדל מעשי, שתיהן מייצגות אותה שגיאה</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. <code>401</code> מוחזר רק מ-<code>GET</code>, ו-<code>403</code> רק מ-<code>POST</code></button>
    <button class="quiz-option" type="button" data-choice="ג">ג. <code>401</code> אומר "מי אתה?" (אין אימות תקין), ו-<code>403</code> אומר "אני יודע מי אתה, אבל אתה לא רשאי"</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. <code>401</code> היא שגיאת שרת, ו-<code>403</code> היא שגיאת לקוח</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> <code>401 Unauthorized</code> מסמן בעיית Authentication - הלקוח לא זוהה כלל או שהאימות שגוי. <code>403 Forbidden</code> מסמן בעיית Authorization - הלקוח כן זוהה, אך אין לו הרשאה לפעולה המבוקשת. זו אחת השאלות הקלאסיות בראיונות עבודה.</div>
</div>

<div class="quiz-card" data-answer="ד">
  <p class="quiz-question"><strong>3. מהו ההבדל המרכזי בין אימות מבוסס <code>JWT</code> לאימות מבוסס Session (Cookies)?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. <code>JWT</code> הוא Stateful (השרת שומר אותו), ו-Session הוא Stateless</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. Session משמש רק ל-Mobile Apps, ו-<code>JWT</code> רק לדפדפנים</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. אין הבדל, שני המונחים מתארים בדיוק את אותה שיטה</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. <code>JWT</code> הוא Stateless (כל המידע נמצא בטוקן עצמו, והשרת רק מוודא חתימה), בעוד Session היא Stateful (השרת חייב לשמור את המידע בזיכרון/DB)</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> Session נפוצה יותר באפליקציות web מסורתיות ודורשת מהשרת "לזכור" את המשתמש. <code>JWT</code> נפוץ יותר ב-APIs ומיקרו-שירותים בדיוק כי הוא Stateless - השרת לא צריך DB לבדוק מי המשתמש, רק לוודא את החתימה הקריפטוגרפית.</div>
</div>

<div class="quiz-card" data-answer="א">
  <p class="quiz-question"><strong>4. לפי Richardson Maturity Model, מה מאפיין API ב-Level 2?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. שימוש נכון ב-HTTP Methods וב-Status Codes - שם נמצאים רוב ה-APIs ה"RESTful" בתעשייה בפועל</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. endpoint יחיד עם method יחיד, הכל בגוף הבקשה (סגנון RPC)</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. תמיכה מלאה ב-HATEOAS בכל תשובה</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. שימוש בלעדי בפרוטוקול GraphQL</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> Level 0 הוא endpoint יחיד בסגנון RPC, Level 1 מוסיף resources/URIs שונים, Level 2 מוסיף שימוש נכון ב-HTTP Methods ו-Status Codes (הרמה שבה נמצאים רוב ה-APIs בתעשייה), ו-Level 3 מוסיף HATEOAS - הנדיר ביותר בפועל.</div>
</div>

<div class="quiz-card" data-answer="ד">
  <p class="quiz-question"><strong>5. איזה מהשינויים הבאים נחשב Breaking Change בגרסת API?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. הוספת שדה חדש אופציונלי לתשובה</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. הוספת endpoint חדש</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. הוספת query parameter אופציונלי</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. הסרת שדה קיים מהתשובה</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> הוספות (שדה אופציונלי, endpoint, query param אופציונלי) הן בדרך כלל לא שוברות. לעומת זאת הסרת שדה, שינוי שם שדה, שינוי סוג נתונים, או הפיכת שדה אופציונלי לחובה - כולן Breaking Changes שעלולות להפיל לקוחות קיימים.</div>
</div>

<div class="quiz-card" data-answer="ג">
  <p class="quiz-question"><strong>6. מהי בעיית ה-N+1 ב-GraphQL, ואיך פותרים אותה בדרך כלל?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. כל שדה בשאילתה דורש הרשאה נפרדת; פותרים עם OAuth</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. חריגה ממכסת בקשות; פותרים עם Token Bucket</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. resolver שולח שאילתת DB נפרדת לכל פריט ברשימה (N פריטים = N+1 שאילתות); פותרים עם DataLoader שמאגד (batches) בקשות דומות לשאילתה אחת</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. בעיית caching של תוצאות; פותרים עם ETag</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> דוגמה קלאסית: להביא N פוסטים ועבור כל אחד לבצע שאילתה נפרדת ל"author" שלו - זה N+1 שאילתות. DataLoader פותר זאת ע"י איגוד (batching) של כל הבקשות הדומות שמצטברות באותו tick לשאילתה אחת מרוכזת.</div>
</div>

<div class="quiz-card" data-answer="ד">
  <p class="quiz-question"><strong>7. מהי הפגיעות Broken Object Level Authorization (<code>BOLA</code>), הראשונה ברשימת OWASP API Security Top 10?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. חולשה בהצפנת החיבור (חוסר HTTPS)</button>
    <button class="quiz-option" type="button" data-choice="ב">ב. חוסר Rate Limiting שמאפשר מתקפת DoS</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. שימוש בסיסמאות חלשות בלבד</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. מצב שבו משתמש מזוהה יכול לגשת לנתונים ששייכים למשתמש אחר, כי השרת בודק רק אימות ולא בעלות (ownership) על המשאב</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> דוגמה טיפוסית: <code>GET /orders/123</code> שמחזיר את ההזמנה בלי לבדוק שהיא שייכת למשתמש המחובר. הפתרון הוא לבדוק בכל endpoint שמקבל ID שה-ownership של המשאב אכן תואם למשתמש המאומת.</div>
</div>

<div class="quiz-card" data-answer="ג">
  <p class="quiz-question"><strong>9. מה תפקידו של <code>ETag</code> בבקשות HTTP, ומה קורה כשהמשאב לא השתנה?</strong></p>
  <div class="quiz-options">
    <button class="quiz-option" type="button" data-choice="א">א. הוא מצפין את גוף התשובה; אם לא השתנה, השרת מחזיר <code>401</code></button>
    <button class="quiz-option" type="button" data-choice="ב">ב. הוא מזהה ייחודי של המשתמש; משמש רק לאימות (Authentication)</button>
    <button class="quiz-option" type="button" data-choice="ג">ג. הוא "טביעת אצבע" של גרסת המשאב; כשהלקוח שולח אותו ב-<code>If-None-Match</code> והמשאב לא השתנה, השרת מחזיר <code>304 Not Modified</code> בלי גוף תשובה</button>
    <button class="quiz-option" type="button" data-choice="ד">ד. הוא קובע כמה בקשות מותרות בדקה מאותו לקוח</button>
  </div>
  <div class="quiz-result" aria-live="polite"></div>
  <div class="quiz-explain"><strong>הסבר:</strong> ה-<code>ETag</code> מאפשר Conditional Requests: הלקוח שולח אותו חזרה ב-Header <code>If-None-Match</code>, ואם המשאב בשרת לא השתנה, מתקבל <code>304 Not Modified</code> ללא גוף תשובה - מה שחוסך bandwidth משמעותית.</div>
</div>

<script>
(function () {
  function initQuiz() {
    var cards = document.querySelectorAll('.quiz-card');
    var scoreEl = document.getElementById('quiz-score');
    var resetAllBtn = document.getElementById('quiz-reset-all');

    function updateScore() {
      if (!scoreEl) return;
      var correctCount = document.querySelectorAll('.quiz-card--answered[data-was-correct="true"]').length;
      scoreEl.textContent = 'ענית נכון על ' + correctCount + ' מתוך ' + cards.length;
    }

    function answerCard(card, chosenBtn) {
      var correct = card.getAttribute('data-answer');
      var chosen = chosenBtn.getAttribute('data-choice');
      var isCorrect = chosen === correct;

      card.classList.add('quiz-card--answered');
      card.setAttribute('data-was-correct', isCorrect ? 'true' : 'false');

      var options = card.querySelectorAll('.quiz-option');
      options.forEach(function (opt) {
        opt.disabled = true;
        if (opt.getAttribute('data-choice') === correct) {
          opt.classList.add('quiz-option--correct');
        } else if (opt === chosenBtn) {
          opt.classList.add('quiz-option--incorrect');
        }
      });

      var result = card.querySelector('.quiz-result');
      if (result) {
        result.textContent = isCorrect ? '✅ נכון!' : '❌ לא נכון - התשובה הנכונה מסומנת בירוק.';
        result.classList.remove('quiz-result--correct', 'quiz-result--incorrect');
        result.classList.add(isCorrect ? 'quiz-result--correct' : 'quiz-result--incorrect');
      }

      updateScore();
    }

    function resetCard(card) {
      card.classList.remove('quiz-card--answered');
      card.removeAttribute('data-was-correct');
      var options = card.querySelectorAll('.quiz-option');
      options.forEach(function (opt) {
        opt.disabled = false;
        opt.classList.remove('quiz-option--correct', 'quiz-option--incorrect');
      });
      var result = card.querySelector('.quiz-result');
      if (result) {
        result.textContent = '';
        result.classList.remove('quiz-result--correct', 'quiz-result--incorrect');
      }
    }

    cards.forEach(function (card) {
      card.querySelectorAll('.quiz-option').forEach(function (btn) {
        btn.addEventListener('click', function () {
          if (card.classList.contains('quiz-card--answered')) return;
          answerCard(card, btn);
        });
      });
    });

    if (resetAllBtn) {
      resetAllBtn.addEventListener('click', function () {
        cards.forEach(resetCard);
        updateScore();
      });
    }

    updateScore();
  }

  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', initQuiz);
  } else {
    initQuiz();
  }
})();
</script>
