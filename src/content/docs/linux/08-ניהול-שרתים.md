# מדריך 8: ניהול שרתים בלינוקס

## מבוא
מדריך זה מרכז נושאי ליבה בניהול שרתי לינוקס בפרודקשן: ניהול חבילות, מוניטורינג, גיבויים, לוגים, ואבטחת שרת.

---

## 1. ניהול חבילות (Package Management)

### APT (Debian/Ubuntu)
```bash
# עדכון רשימת החבילות הזמינות
sudo apt update

# שדרוג כל החבילות המותקנות
sudo apt upgrade -y

# התקנת חבילה
sudo apt install nginx

# הסרת חבילה
sudo apt remove nginx

# הסרה כולל קבצי קונפיגורציה
sudo apt purge nginx

# ניקוי חבילות תלויות שכבר לא נחוצות
sudo apt autoremove

# חיפוש חבילה
apt search nginx

# הצגת מידע על חבילה
apt show nginx
```

### YUM/DNF (RHEL/CentOS/Fedora)
```bash
sudo dnf install nginx
sudo dnf update
sudo dnf remove nginx
sudo dnf search nginx
```

### ניהול חבילות עצמאיות
```bash
# התקנת קובץ .deb
sudo dpkg -i package.deb
sudo apt install -f   # תיקון תלויות חסרות

# התקנת קובץ .rpm
sudo rpm -ivh package.rpm
```

## 2. גיבויים ושחזור

```bash
# גיבוי מלא של תיקייה עם דחיסה
tar -czvf backup-$(date +%Y%m%d).tar.gz /var/www/html

# גיבוי inkremental עם rsync
rsync -avz --link-dest=/backups/latest /source/ /backups/$(date +%Y%m%d)/

# גיבוי מסד נתונים MySQL
mysqldump -u root -p database_name > backup.sql

# שחזור מסד נתונים
mysql -u root -p database_name < backup.sql

# גיבוי PostgreSQL
pg_dump database_name > backup.sql
psql database_name < backup.sql

# אוטומציה עם cron - גיבוי יומי ב-2 לפנות בוקר
# 0 2 * * * /opt/scripts/backup.sh
```

## 3. מוניטורינג ובריאות המערכת

```bash
# עומס מערכת ממוצע (load average) ב-1, 5, 15 דקות
uptime
cat /proc/loadavg

# שימוש מפורט ב-CPU
mpstat 1 5

# ניטור I/O דיסק
iostat -x 1

# בדיקת בריאות דיסק (SMART)
sudo smartctl -a /dev/sda

# ניטור זיכרון בזמן אמת
watch -n 1 free -h

# בדיקת תהליכים שצורכים הכי הרבה משאבים
ps aux --sort=-%cpu | head -10
ps aux --sort=-%mem | head -10
```

### כלים מתקדמים למוניטורינג פרודקשן
- **Prometheus + Grafana** - ניטור מדדים והתראות
- **Nagios / Zabbix** - ניטור זמינות שירותים ותשתית
- **ELK Stack (Elasticsearch, Logstash, Kibana)** - ריכוז וניתוח לוגים
- **Netdata** - ניטור בזמן אמת בממשק גרפי, קל להתקנה

## 4. ניהול לוגים

```bash
# מיקומי לוגים חשובים
/var/log/syslog        # לוג מערכת כללי (Debian/Ubuntu)
/var/log/messages      # לוג מערכת כללי (RHEL/CentOS)
/var/log/auth.log      # לוגים של אימות והתחברויות
/var/log/nginx/        # לוגי nginx
/var/log/mysql/        # לוגי MySQL

# ניהול רוטציית לוגים - logrotate
cat /etc/logrotate.conf
sudo logrotate -f /etc/logrotate.conf   # הפעלה ידנית

# בדיקת קונפיגורציה של שירות ספציפי ברוטציה
cat /etc/logrotate.d/nginx
```

דוגמת קובץ logrotate:
```
/var/log/myapp/*.log {
    daily
    rotate 14
    compress
    missingok
    notifempty
    create 0640 www-data adm
}
```

## 5. אבטחת שרת (Server Hardening) - עקרונות בסיס

```bash
# עדכון קבוע של המערכת
sudo apt update && sudo apt upgrade -y

# השבתת שירותים לא נחוצים
sudo systemctl disable --now bluetooth

# הגדרת fail2ban - חסימת IP אחרי ניסיונות כניסה כושלים
sudo apt install fail2ban
sudo systemctl enable --now fail2ban
fail2ban-client status sshd

# בדיקת ניסיונות התחברות כושלים
sudo grep "Failed password" /var/log/auth.log

# הגבלת גישת SSH רק למפתחות (ולא סיסמאות)
# ב-/etc/ssh/sshd_config: PasswordAuthentication no

# בדיקת חבילות עם עדכוני אבטחה זמינים
sudo apt list --upgradable
```

## 6. וירטואליזציה וקונטיינרים


## 7. High Availability & Load Balancing - מושגים

- **Load Balancer** (Nginx, HAProxy) - מפזר תעבורה בין מספר שרתים.
- **Reverse Proxy** - שרת שמקבל בקשות בשם שרתים אחרים (Nginx נפוץ מאוד לתפקיד זה).
- **Health Checks** - בדיקות תקינות אוטומטיות שמסירות שרת לא תקין מרוטציית ה-load balancer.

דוגמת קונפיגורציית Nginx כ-reverse proxy:
```nginx
server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## טיפים וטריקים 🔥

1. תמיד בדקו `df -h` לפני עדכוני מערכת גדולים - חוסר מקום בדיסק יכול לשבור עדכון באמצע.
2. השתמשו ב-`unattended-upgrades` (Ubuntu/Debian) להתקנה אוטומטית של עדכוני אבטחה קריטיים.
3. בצעו גיבויים לפי כלל 3-2-1: 3 עותקים, על 2 סוגי מדיה שונים, 1 עותק במיקום חיצוני (offsite).
4. `fail2ban` הוא must-have לכל שרת עם SSH פתוח לאינטרנט.
5. תעדו כל שינוי קונפיגורציה ב-Git (Infrastructure as Code) - גם קבצי nginx/systemd, לא רק קוד אפליקציה.
6. תמיד בדקו לוגים אחרי כל deploy או שינוי קונפיגורציה משמעותי.

## שאלות ראיון עבודה נפוצות

1. **מה ההבדל בין `apt update` ל-`apt upgrade`?**
   `update` מרענן את רשימת החבילות הזמינות מהמאגרים (לא מתקין כלום). `upgrade` בפועל משדרג את החבילות המותקנות לגרסאות העדכניות.

2. **איך תגבו מסד נתונים MySQL ותשחזרו אותו?**
   גיבוי: `mysqldump -u root -p dbname > backup.sql`. שחזור: `mysql -u root -p dbname < backup.sql`

3. **מה זה logrotate ולמה הוא חשוב?**
   כלי שמנהל את מחזור החיים של קבצי לוג - מונע מהם לתפוס את כל שטח הדיסק ע"י דחיסה, מחיקה או ארכוב לוגים ישנים בהתאם למדיניות מוגדרת.

4. **מהם עקרונות "כלל 3-2-1" בגיבויים?**
   3 עותקים של הנתונים, על 2 סוגי מדיה שונים, כאשר עותק אחד לפחות נמצא offsite (מיקום חיצוני) להגנה מפני אסון פיזי.

5. **מה תפקידו של fail2ban?**
   מנטר לוגים (בעיקר SSH) ומזהה ניסיונות כניסה כושלים חוזרים, וחוסם אוטומטית את כתובת ה-IP התוקפת דרך הfirewall למניעת brute-force attacks.

6. **מה ההבדל בין reverse proxy ל-load balancer?**
   Reverse proxy מקבל בקשות בשם שרת/שרתים ומעביר אותן הלאה (יכול לשמש גם ל-SSL termination, caching). Load balancer מתמחה בחלוקת עומס בין מספר שרתים לפי אלגוריתם (round-robin, least connections וכו') - Nginx יכול לשמש בשני התפקידים.
