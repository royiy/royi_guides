# מדריך 5: ניהול תהליכים (Process Management)

## מבוא
כל פעולה בלינוקס - מהרצת פקודה ועד שירות רקע - היא תהליך (process). מדריך זה מסביר כיצד לצפות, לנטר ולשלוט בתהליכים.

---

## 1. צפייה בתהליכים

```bash
# רשימת כל התהליכים הרצים (סטטי)
ps aux

# רשימת תהליכים בעץ היררכי
ps -ejH
pstree

# ניטור בזמן אמת - top
top

# ניטור בזמן אמת משודרג - htop (דורש התקנה, הרבה יותר נוח)
htop

# חיפוש תהליך ספציפי לפי שם
ps aux | grep nginx
pgrep nginx

# הצגת PID בלבד
pgrep -l nginx
```

### הבנת פלט `ps aux`
```
USER   PID  %CPU %MEM  VSZ   RSS TTY  STAT START TIME COMMAND
root   1234  0.5  1.2  50000 8000 ?    Ss   10:00 0:05 nginx: master
```
- **PID** - מזהה ייחודי לתהליך
- **%CPU / %MEM** - אחוז ניצול משאבים
- **STAT** - מצב התהליך (R=running, S=sleeping, Z=zombie, D=uninterruptible sleep)

---

## 2. עצירת וניהול תהליכים

```bash
# עצירה רגילה (בקשה מנומסת לתהליך להיסגר)
kill PID

# עצירה מיידית וכפויה (לא ניתן להתעלם)
kill -9 PID
kill -SIGKILL PID

# עצירה עדינה יותר (מאפשרת ניקוי משאבים)
kill -15 PID
kill -SIGTERM PID

# עצירת כל התהליכים בשם מסוים
killall nginx
pkill -f "python script.py"

# רענון קונפיגורציה בלי restart מלא (למשל nginx)
kill -HUP PID
```

### טבלת אותות (Signals) נפוצים
| אות | מספר | משמעות |
|---|---|---|
| SIGHUP | 1 | Hang up - לרוב מאותת לתהליך לטעון קונפיגורציה מחדש |
| SIGINT | 2 | הפסקה (כמו Ctrl+C) |
| SIGKILL | 9 | הרג מיידי - לא ניתן לתפוס/להתעלם |
| SIGTERM | 15 | בקשת סיום מנומסת (ברירת מחדל של kill) |
| SIGSTOP | 19 | השהיה |

## 3. עדיפות תהליכים (Priority / Nice)

```bash
# הרצת תהליך בעדיפות נמוכה (nice value גבוה = פחות עדיפות)
nice -n 10 ./heavy_script.sh

# שינוי עדיפות של תהליך רץ
renice -n 5 -p PID

# טווח nice: -20 (עדיפות מקסימלית) עד 19 (עדיפות מינימלית)
```

## 4. תהליכי רקע ו-Foreground

```bash
# הרצת פקודה ברקע
./long_script.sh &

# הצגת עבודות רקע פעילות
jobs

# החזרת עבודת רקע ל-foreground
fg %1

# העברת תהליך פועל לרקע (לאחר Ctrl+Z להשהות אותו)
bg %1

# הרצת פקודה שתמשיך גם אם ה-terminal נסגר
nohup ./script.sh &

# כלי מומלץ לניהול sessions ארוכי טווח - screen / tmux
screen -S mysession
tmux new -s mysession
```

## 5. ניטור ביצועים

```bash
# שימוש בזיכרון בזמן אמת
free -h

# ניטור I/O של דיסק
iostat -x 1

# ניטור פעילות רשת לפי תהליך
nethogs

# ניטור מפורט של תהליך בודד
top -p PID

# רשימת קבצים פתוחים ע"י תהליך
lsof -p PID

# בדיקת אילו תהליכים משתמשים בפורט מסוים
lsof -i :80
sudo ss -tulpn | grep :80
```

## 6. תהליכי Zombie ו-Orphan

- **Zombie process** - תהליך שסיים לרוץ אך ה-process table entry שלו עדיין קיים כי ה-parent לא "אסף" (wait) את קוד היציאה שלו.
- **Orphan process** - תהליך שה-parent שלו נסגר; מאומץ אוטומטית ע"י init/systemd (PID 1).

```bash
# איתור zombie processes
ps aux | grep 'Z'
```
פתרון ל-zombie: לרוב יש לתקן את ה-parent process (bug בקוד) - לא ניתן להרוג zombie ישירות כי הוא כבר "מת".

## טיפים וטריקים 🔥

1. השתמשו ב-`htop` על פני `top` - ממשק צבעוני, נוח יותר לסינון ולהרוג תהליכים.
2. `kill -9` הוא מוצא אחרון - הוא לא מאפשר לתהליך לנקות משאבים (סגירת קבצים, חיבורי DB וכו').
3. `tmux`/`screen` הכרחיים לעבודה על שרתים מרוחקים - הסשן ממשיך לרוץ גם אם החיבור נופל.
4. `watch -n 1 'command'` מריץ פקודה כל שנייה ומציג את הפלט המתעדכן.
5. תמיד בדקו `lsof -i :PORT` לפני שאתם מנסים להפעיל שירות שנכשל עם "port already in use".

## שאלות ראיון עבודה נפוצות

1. **מה ההבדל בין SIGTERM ל-SIGKILL?**
   SIGTERM (15) מבקש מהתהליך להיסגר בצורה מסודרת ומאפשר לו "לנקות" משאבים. SIGKILL (9) הורג את התהליך מיידית ללא אפשרות תגובה מצד התהליך.

2. **מהו zombie process וכיצד מטפלים בו?**
   תהליך שסיים לרוץ אך רשומתו לא נוקתה כי ה-parent לא ביצע wait(). הפתרון האמיתי הוא תיקון ה-parent process; לא ניתן "להרוג" zombie.

3. **איך תבדקו איזה תהליך מאזין על פורט 8080?**
   `sudo lsof -i :8080` או `sudo ss -tulpn | grep 8080`

4. **מה ההבדל בין `&` ל-`nohup`?**
   `&` מריץ ברקע אך התהליך עדיין מקושר לטרמינל וייסגר אם הטרמינל נסגר (SIGHUP). `nohup` מתעלם מ-SIGHUP ומאפשר לתהליך להמשיך לרוץ גם אחרי סגירת הטרמינל.

5. **מהו PID 1 ומה תפקידו?**
   התהליך הראשון שרץ בעת אתחול המערכת (init/systemd). הוא "מאמץ" תהליכי orphan ואחראי על ניהול כל שאר התהליכים במערכת.
