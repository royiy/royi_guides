# מדריך 10: שאלות ראיון עבודה מרוכזות וטיפים כלליים ללינוקס

## מבוא
מדריך מסכם זה אוסף שאלות ראיון עבודה נפוצות לתפקידי Linux/DevOps/SysAdmin ברמות שונות, יחד עם טיפים כלליים לעבודה יומיומית עם לינוקס.

---

## חלק א': שאלות ראיון - רמה בסיסית (Junior)

1. **מה ההבדל בין לינוקס לויינדוס?**
   לינוקס היא מערכת קוד פתוח מבוססת Unix, מודולרית, עם שליטה מלאה בשורת פקודה. תומכת ב-multi-user אמיתי, הרשאות קפדניות, וגמישות רבה בהתאמה אישית.

2. **מה זה קרנל (Kernel)?**
   הליבה של מערכת ההפעלה - האחראית לתקשורת ישירה עם החומרה, ניהול זיכרון, תהליכים, ומערכת קבצים.

3. **מה ההבדל בין הפצות לינוקס שונות (Ubuntu, CentOS, Debian)?**
   כולן מבוססות על אותו קרנל לינוקס, אך נבדלות בכלי ניהול חבילות (apt vs yum/dnf), מדיניות עדכונים, קהילת תמיכה, ומטרת שימוש (Ubuntu ידידותי, CentOS/RHEL יציב לארגונים).

4. **מהי מערכת הקבצים ההיררכית (FHS) בלינוקס?**
   | תיקייה | תפקיד |
   |---|---|
   | `/` | שורש המערכת |
   | `/bin`, `/usr/bin` | תוכניות בסיסיות |
   | `/etc` | קבצי קונפיגורציה |
   | `/home` | תיקיות הבית של משתמשים |
   | `/var` | נתונים משתנים (לוגים, קאש) |
   | `/tmp` | קבצים זמניים |
   | `/opt` | תוכנות צד שלישי |
   | `/proc` | מידע וירטואלי על תהליכים |

5. **מה ההבדל בין soft-link ל-hard-link?**
   ראו הרחבה במדריך 02.

## חלק ב': שאלות ראיון - רמה בינונית (Mid-level)

6. **הסבירו את תהליך ה-boot של לינוקס.**
   BIOS/UEFI → Bootloader (GRUB) → טעינת קרנל → אתחול systemd (PID 1) → הפעלת שירותים לפי target → login prompt.

7. **מה ההבדל בין load average גבוה לשימוש CPU גבוה?**
   Load average מודד תהליכים הממתינים למשאבים (CPU **וגם** I/O), בעוד שימוש CPU מודד רק ניצול מעבד בפועל. שרת יכול להראות load average גבוה עם CPU נמוך אם יש הרבה תהליכים תקועים ב-I/O wait.

8. **איך תדבגו שרת שחסר בו זיכרון (Out of Memory)?**
   `free -h`, `dmesg | grep -i oom`, בדיקת `/var/log/syslog` לאירועי OOM Killer, ובדיקת תהליכים כבדים עם `ps aux --sort=-%mem`.

9. **מה זה swap ומתי הוא בעייתי?**
   שטח דיסק המשמש כזיכרון וירטואלי כשה-RAM מתמלא. שימוש כבד ב-swap מעיד על מחסור בזיכרון פיזי ומאט משמעותית את המערכת (כי דיסק איטי בהרבה מ-RAM).

10. **הסבירו את ההבדל בין process ל-thread.**
    Process הוא יחידת ריצה עצמאית עם מרחב זיכרון משלה. Thread הוא יחידת ריצה בתוך process שחולק את אותו מרחב זיכרון עם threads אחרים באותו process - קליל יותר ליצירה אך פחות מבודד.

11. **איך תמצאו מה גורם לעומס גבוה על שרת בזמן אמת?**
    `top`/`htop` לזיהוי תהליכים כבדים, `iostat` לבדיקת I/O דיסק, `vmstat` לניתוח כללי, ו-`iotop` לזיהוי תהליכים כבדי דיסק.

12. **מה ההבדל בין hard limit ל-soft limit (ulimit)?**
    Soft limit הוא הגבול הנוכחי בפועל (ניתן להעלאה ע"י המשתמש עד ה-hard limit). Hard limit הוא התקרה המקסימלית שרק root יכול לשנות.

## חלק ג': שאלות ראיון - רמה מתקדמת (Senior/DevOps)

13. **תארו תרחיש שבו שרת production נפל - איך תגשו לחקירה (troubleshooting)?**
    תשובה מומלצת: קודם `systemctl status`/`journalctl` לבדיקת סטטוס שירותים, בדיקת לוגים רלוונטיים, `dmesg` לאירועי קרנל, `df -h` לבדיקת מקום בדיסק, `free -h` לזיכרון, `top`/`htop` לעומס, ואז חזרה אחורה בזמן לזיהוי מתי בעיה התחילה (deploy אחרון? שינוי קונפיגורציה?).

14. **מה ההבדל בין containers ל-virtual machines?**
    VMs מדמים חומרה שלמה כולל קרנל נפרד לכל VM (דרך hypervisor) - בידוד מלא אך overhead גבוה. Containers (Docker) חולקים את אותו קרנל של host ומבודדים ברמת ה-namespace/cgroups - קלילים ומהירים יותר, אך בידוד פחות מלא.

15. **מה זה cgroups ו-namespaces ואיך הם קשורים לקונטיינרים?**
    `cgroups` (control groups) מגבילים ומקצים משאבים (CPU, memory, I/O) לקבוצת תהליכים. `namespaces` מבודדים משאבי מערכת (PID, network, mount, user) כך שתהליך "רואה" רק חלק מהמערכת - יחד הם הבסיס הטכני שעליו בנויים Docker וטכנולוגיות קונטיינרים אחרות.

16. **איך תתכננו אסטרטגיית high availability לשירות קריטי?**
    Load balancer מול מספר instances, health checks אוטומטיים, database replication (master-slave/multi-master), auto-scaling, וגיבויים אוטומטיים עם תוכנית DR (Disaster Recovery) מתועדת ובדוקה.

17. **מה ההבדל בין orchestration (כמו Kubernetes) לניהול שרתים ידני?**
    Orchestration מאפשר ניהול אוטומטי של deployment, scaling, self-healing (הפעלה מחדש אוטומטית של containers שנכשלו), ו-service discovery - קריטי בסביבות עם עשרות/מאות שירותים, לעומת ניהול ידני שמתאים לסביבות קטנות בלבד.

18. **איך תגשו לאבטחת שרת חדש (server hardening checklist)?**
    - עדכון מערכת מלא
    - ביטול root login דרך SSH
    - הגדרת אימות מבוסס מפתח בלבד (לא סיסמה)
    - הגדרת firewall עם עקרון deny-by-default
    - התקנת fail2ban
    - סגירת שירותים לא נחוצים
    - הגדרת ניטור ו-alerting
    - עדכוני אבטחה אוטומטיים

## חלק ד': טיפים כלליים לעבודה יומיומית עם לינוקס 🔥

1. **למדו לקרוא man pages** - `man command` הוא מקור האמת הראשון, לפני חיפוש בגוגל.
2. **תעדו כל שינוי קונפיגורציה** - הוסיפו הערה עם תאריך ליד כל שינוי בקבצי קונפיגורציה קריטיים.
3. **גבו לפני עריכה** - `cp file.conf file.conf.bak.$(date +%Y%m%d)` לפני כל עריכה של קובץ קריטי.
4. **השתמשו ב-Git לניהול קונפיגורציה** - גם קבצי systemd/nginx/cron ראויים לניהול גרסאות.
5. **בנו סקריפטים אידמפוטנטיים** - הרצה חוזרת של אותו סקריפט לא אמורה לגרום נזק (בדקו לפני שאתם יוצרים/מוחקים).
6. **השתמשו ב-tmux/screen** בעבודה מרוחקת - מונע אובדן עבודה בעת ניתוק חיבור.
7. **תרגלו troubleshooting שיטתי** - התחילו רחב (מערכת → שירות → אפליקציה → קוד) ולא הפוך.
8. **הכירו את כלי הניטור המובנים** - `top`, `free`, `df`, `journalctl` - אלה זמינים תמיד, גם בלי כלים חיצוניים.
9. **אל תעבדו כ-root כברירת מחדל** - השתמשו ב-`sudo` לפקודות ספציפיות בלבד.
10. **התעדכנו בקהילה** - עקבו אחרי בלוגים ופורומים כמו Stack Overflow, Server Fault, ו-r/linuxadmin.
