## מהי הנדסת פרומפטים?

הנדסת פרומפטים היא האומנות והמדע של כתיבת הוראות (פרומפטים) יעילות למודלי שפה, כדי לקבל את התוצאות הטובות ביותר — מדויקות, שימושיות ורלוונטיות. זהו מיומנות מפתח לכל מי שעובד עם LLM, בין אם למטרות פיתוח, עסקים, או שימוש אישי.

## עקרונות יסוד

### 1. בהירות וספציפיות (Clarity & Specificity)
ככל שהפרומפט ברור ומדויק יותר, כך התשובה תהיה טובה יותר.

**דוגמה גרועה:** "כתוב לי משהו על שיווק"

**דוגמה טובה:** "כתוב פוסט של 200 מילים לרשת חברתית (LinkedIn) על חשיבות ה-SEO לעסקים קטנים, בטון מקצועי אך ידידותי, עם 3 טיפים מעשיים בסוף"

### 2. מתן דוגמאות (Few-Shot Prompting)
נתינת דוגמאות קונקרטיות עוזרת למודל להבין בדיוק את הפורמט והסגנון הרצויים.

```
המר את המשפטים הבאים לפורמט JSON:

דוגמה 1:
קלט: "יוסי בן 30, גר בתל אביב"
פלט: {"שם": "יוסי", "גיל": 30, "עיר": "תל אביב"}

דוגמה 2:
קלט: "רותי בת 25, גרה בחיפה"
פלט: {"שם": "רותי", "גיל": 25, "עיר": "חיפה"}

עכשיו המר:
קלט: "דני בן 40, גר בירושלים"
פלט:
```

### 3. חשיבה שלב-אחר-שלב (Chain of Thought - CoT)
בקשה מהמודל "לחשוב בקול" משפרת דרמטית ביצועים במשימות הסקה מורכבות.

```
פתור את הבעיה הבאה, שלב אחר שלב:

בחנות יש 120 עטים. נמכרו 35% מהם ביום ראשון,
ו-20% מהנותרים נמכרו ביום שני.
כמה עטים נותרו בסוף יום שני?

חשוב שלב אחר שלב לפני שאתה נותן תשובה סופית.
```

### 4. הגדרת תפקיד (Role Prompting)
"אתה מומחה למיסים ישראלי עם 20 שנות ניסיון..." — נותן למודל "פרסונה" שמשפיעה על סגנון ותוכן התשובה.

### 5. שימוש בתגיות XML לצורך מבנה
מודלים כמו Claude מגיבים היטב לתיוג בעזרת XML tags:

```xml
<instructions>
תרגם את הטקסט הבא לאנגלית, שמור על הטון המקורי.
</instructions>

<text>
שלום, מה שלומך היום? אני מקווה שהכל בסדר.
</text>

<output_format>
החזר רק את התרגום, ללא הערות נוספות.
</output_format>
```

## טכניקות מתקדמות

### Zero-Shot vs Few-Shot vs Chain-of-Thought
| טכניקה | מתי להשתמש |
|---|---|
| Zero-Shot | משימות פשוטות וברורות ("סכם את הטקסט") |
| Few-Shot | כשצריך פורמט מדויק או סגנון ספציפי |
| Chain-of-Thought | בעיות מתמטיות, לוגיות, או ריבוי-שלבים |
| Self-Consistency | הרצת אותה שאלה מספר פעמים ובחירת התשובה הנפוצה ביותר |
| ReAct (Reason + Act) | שילוב הסקה עם שימוש בכלים חיצוניים |

### Prompt Chaining
פירוק משימה מורכבת לכמה פרומפטים עוקבים, כשפלט של אחד הוא קלט של הבא. לדוגמה: פרומפט 1 — כתוב טיוטה, פרומפט 2 — בקר איכות וערוך, פרומפט 3 — עצב לפורמט סופי.

### System Prompts
הוראות "מאחורי הקלעים" שקובעות את התנהגות המודל לאורך כל השיחה:

```python
import anthropic

client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=500,
    system="אתה עוזר תמיכה טכני לחברת תוכנה. ענה תמיד בעברית, בטון סבלני ומקצועי, ואל תמציא פרטים שאינך יודע.",
    messages=[{"role": "user", "content": "המערכת שלי קורסת כשאני מנסה לשמור קובץ"}]
)
print(response.content[0].text)
```

## טעויות נפוצות שכדאי להימנע מהן

1. **פרומפטים עמומים** — "תעשה משהו טוב" לא נותן למודל כיוון.
2. **בקשות סותרות** — "תהיה קצר אבל תסביר הכל בפירוט" מבלבל את המודל.
3. **חוסר בהגדרת פורמט פלט** — אם אתם צריכים JSON, בקשו JSON במפורש.
4. **אי מתן הקשר מספיק** — המודל לא "יודע" מה אינכם אומרים לו.
5. **פרומפט ארוך מדי וללא מבנה** — עדיף לחלק לסעיפים ברורים (הוראות, הקשר, דוגמאות, פורמט פלט).

## טיפים וטריקים

- **בקשו מהמודל "לחשוב לפני שהוא עונה"** — משפר דיוק במשימות מורכבות.
- **תנו למודל "מסגרת יציאה"** — למשל "אם אינך בטוח, ענה 'לא ידוע' במקום לנחש".
- **בדקו איטרטיבית** — כתבו פרומפט, בדקו תוצאה, שפרו. פרומפט מעולה כמעט תמיד דורש כמה גרסאות.
- **השתמשו ב-Delimiters** (מפרידים ברורים כמו `"""` או תגיות XML) כדי להפריד בין הוראות לתוכן.
- **בקשו "פורמט פלט" מפורש** — טבלה, JSON, רשימה ממוספרת וכו'.
- **למשימות רגישות** — בקשו מהמודל לצטט מקורות או להסביר את ההיגיון מאחורי המסקנה.
