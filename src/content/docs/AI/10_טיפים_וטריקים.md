## חלק א': טיפים לעבודה יעילה עם Claude / ChatGPT / Gemini

1. **תנו הקשר מלא בפעם אחת** — במקום לפרק שאלה למספר הודעות, תנו את כל המידע הרלוונטי בבת אחת. זה חוסך "הלוך ושוב" ומשפר דיוק.
2. **בקשו מהמודל "לחשוב לפני שהוא עונה"** — במיוחד במשימות מתמטיות, לוגיות, או ריבוי-שלבים.
3. **פצלו משימות ענקיות** — במקום "כתוב לי אפליקציה שלמה", בקשו קודם תכנון ארכיטקטורה, ואז מימוש שלב אחר שלב.
4. **השתמשו ב"מצב עריכה" איטרטיבי** — קבלו טיוטה ראשונית, ואז בקשו שיפורים ממוקדים ("קצר את הפסקה השנייה", "הוסף דוגמת קוד").
5. **ציינו פורמט פלט מפורש** — "החזר טבלה", "החזר JSON בלבד", "עד 100 מילים" — מונע ניחושים.
6. **בדקו עובדות קריטיות** — במיוחד תאריכים, נתונים סטטיסטיים, ומידע משפטי/רפואי — אמתו במקור חיצוני.

## חלק ג': טריקים מתקדמים בפרומפטינג

### טריק 1: "חשוב על זה מכמה זוויות"
```
לפני שתענה, שקול לפחות 3 גישות שונות לפתרון הבעיה,
והצג את היתרונות והחסרונות של כל אחת. לאחר מכן בחר
את הגישה הטובה ביותר ונמק את בחירתך.
```

### טריק 2: בקשת ביקורת עצמית (Self-Critique)
```
כתוב תשובה ראשונית לשאלה הבאה. לאחר מכן, בקר את התשובה
שלך בעצמך - מצא חולשות ופערים - ולבסוף כתוב גרסה משופרת.
```

### טריק 3: הגבלת אורך תשובה בצורה מדויקת
במקום "תהיה קצר", בקשו מספר מדויק: "עד 3 משפטים", "טבלה עם 5 שורות בדיוק".

### טריק 4: "עצור ושאל אם משהו לא ברור"
```
אם משהו בבקשה שלי לא ברור מספיק כדי לתת תשובה מדויקת,
שאל אותי שאלת הבהרה אחת לפני שתמשיך.
```

## חלק ד': ניהול עלויות (Cost Optimization)

- **בחרו את גודל המודל הנכון למשימה** — לא כל משימה זקוקה למודל ה"פרימיום" הכי גדול; מודלים קטנים וזולים (כמו Haiku, GPT-4o-mini) מספיקים למשימות פשוטות.
- **נצלו Prompt Caching** — אם אתם שולחים אותו הקשר ארוך שוב ושוב (system prompt, מסמכים), caching חוסך עלות משמעותית.
- **הגבילו max_tokens** — מנעו תשובות ארוכות מיותר מהנדרש.
- **Batch Processing** — עבור עיבוד גדול (לא בזמן אמת), שימוש ב-Batch API מוזיל עלויות משמעותית.
- **נטרו שימוש** — בנו dashboards למעקב עלויות לפי feature/משתמש, כדי לזהות "דליפות" מוקדם.

## חלק ה': אבטחה ובטיחות (Security & Safety)

- **אל תזינו מידע רגיש ל-prompt ללא הצפנה/אנונימיזציה** אם אינכם בטוחים במדיניות שמירת הנתונים של הספק.
- **היזהרו מ-Prompt Injection** בתוכן חיצוני (מסמכים, אתרים, מיילים) שהמודל קורא — תוכן זדוני יכול לנסות "לשכנע" את המודל לסטות מהוראותיו.
- **הגבילו הרשאות כלים** — אם סוכן AI יכול לבצע פעולות (מחיקה, תשלום, שליחת מייל), הוסיפו אישור אנושי (human-in-the-loop) לפעולות קריטיות.
- **בדקו פלט לפני שהוא "יוצא לעולם"** — במיוחד בתוכן שמוצג ללקוחות, מומלץ שכבת בדיקה נוספת (guardrails).

## חלק ו': טעויות נפוצות שכדאי להימנע מהן

1. **סמיכה עיוורת על תשובות עובדתיות** ללא אימות.
2. **פרומפטים ארוכים מדי וללא מבנה** — מבלבלים את המודל ומקשים על תחזוקה.
3. **התעלמות מ-Context Window** — שיחות ארוכות "שוכחות" מידע מוקדם.
4. **אי בדיקת עלויות** לפני הרצת עיבוד מסיבי.
5. **בניית פיצ'ר שלם לפני בדיקת proof-of-concept קטן** — התחילו קטן, ולמדו איפה המודל "נכשל" לפני שמשקיעים בבנייה מלאה.

## רשימת בדיקה (Checklist) לפני העלאת פיצ'ר AI לפרודקשן

- [ ] נבדק על מגוון תרחישי קצה (edge cases)?
- [ ] יש מנגנון fallback אם המודל נכשל/לא זמין?
- [ ] יש הגבלת עלויות (budget caps, rate limiting)?
- [ ] יש ניטור (logging, monitoring) לתשובות ולביצועים?
- [ ] נבדקה אבטחה (prompt injection, הרשאות כלים)?
- [ ] יש מנגנון משוב ממשתמשים לשיפור מתמשך?
- [ ] תשובות רגישות עוברות guardrails/בדיקה נוספת?
